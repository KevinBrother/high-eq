# 情商训练APP：产品与技术架构

更新：2026-11-21

## 产品闭环与用户流程

产品围绕一个闭环：测评 → 学习 → 练习 → 实战 → 复盘 → 成长。核心是两个越用越准的画像：用户自己的情绪画像，和他身边重要的人的画像。评测与训练标准见另一份文档《情商训练APP：标准体系与评分规范》。

1. **首次进入**：做 WLEIS 测评，选最想改善的场景（职场、伴侣、家人、朋友、社交），只介绍手表和麦克风，实际启用时再单独授权；生成四维雷达图和第一份训练计划。
2. **建立关系人**：添加领导、伴侣、父母等重要的人，回答几个关于对方的问题，生成初始画像。
3. **日常使用**，两条线并行：
    - 主动练习：每日小练习、知识卡片、和 AI 扮演的关系人预演；
    - 实战辅助：聊天回复助手、手表情绪提醒、事后复盘。
4. **持续反馈**：每次实战后反馈效果，同时修正用户画像和关系人画像。
5. **阶段回顾**：每四周复测一次，对比雷达图变化，调整训练计划。

## 功能体系

功能按用户卡住的四个时刻来设计，再加上贯穿始终的支撑功能。这是完整产品蓝图，优先级在排期时再定。

| 时刻 | 用户问题 | 对应功能 |
| --- | --- | --- |
| 事前 | 要面对一个难的对话 | AI 预演：AI 扮演对方陪练，练完打分并给出更好的说法 |
| 事中 | 正在聊天，不知道怎么回 | 聊天回复助手：分析对方情绪和需求，给出几种回复并说明理由 |
| 事中 | 自己上头了却没察觉 | 情绪提醒：放行的 Apple Watch 实时心率异常加同窗语音异常才可轻震；仅语音双异常只提示对话节奏，不自动更新个人画像 |
| 事后 | 搞砸了，或觉得哪里不对 | 复盘：回听标出的片段，按 NVC 四步分析，生成修复关系的话 |

支撑功能：

- **场景分类**：职场、伴侣、家人、朋友、陌生社交，功能可按场景切换，本轮评分权重不随场景变化。
- **关系人画像**：用大五人格、Thomas-Kilmann 冲突风格、依恋类型做骨架；由问答和聊天记录推断初始画像并标明把握度，再靠用户反馈修正。
- **知识卡片**：短小的原理讲解，嵌在练习里。
- **每日小练习**：几分钟的读人小题或表达小关卡。
- **个性化路径**：按测评结果和画像自动排训练计划。
- **激励与成长档案**：打卡、阶段成就、四维雷达图前后对比。

## 整体架构

三层结构：Flutter 客户端、Go 后端、AI 层；所有 AI 调用都经模型网关，运营后台改配置即可换模型。

```text
整体架构（原文档中为一张图）
客户端：Apple Watch（Swift：心率、震动提醒） → Flutter App（界面 · 本地语音分析） ← 健康平台（苹果 / 安卓 / 华为健康）
运营后台（换模型 · 看板） ──模型与提示词配置──┐
Flutter App ──只上传特征，不传录音──→ 后端（Go 单体，按模块划分）
    用户与会员 · 测评 · 情绪识别 · 画像 · 训练计划
    PostgreSQL · Redis
后端 ──按任务名调用──→ AI 层：模型网关（统一接口 · 按任务路由 · 备用切换 · 调用监控）
    ├→ 云端大模型 API（DeepSeek · 通义千问 · 豆包）
    └→ 私有部署 / 微调模型（vLLM · Qwen · DeepSeek）
```

录音在手机本地分析，只有特征进入后端；后端模块只写任务名，由网关决定调云端还是私有模型。

## 客户端与手表端

客户端用 Flutter 一套代码覆盖 iOS 和安卓；只有 Apple Watch 需要单独写一个很小的原生应用。

| 部分 | 方案 | 说明 |
| --- | --- | --- |
| 手机 App | Flutter | 测评、对练、复盘、成长档案等全部界面 |
| 健康数据 | `health` 插件；华为运动健康官方 Flutter 插件 | 读 Apple 健康（HealthKit）和安卓 Health Connect 的心率、HRV |
| 录音与语音分析 | `record` 插件 + 本地计算 | 音量、音调本地算；语速只用 finalized 的设备端离线转写，按 Unicode 字母/数字 grapheme 数 ÷ 有效转写秒数计算，并标记 `characters_per_second`；无标记旧声学代理不进入该信号 |
| 鸿蒙 | 本轮不做 | 仅交付 iOS 和安卓 |
| Apple Watch | Swift 原生小应用 + WatchConnectivity | 只负责持续读心率和震动提醒，与手机通信 |
| 安卓 / 华为手表 | 不单独开发 | 数据同步到手机健康平台后由 App 读取，可能有几十秒到几分钟延迟 |

安卓和华为手表本轮只供基线和事后复盘，手机可显示对话节奏提示，不发本人情绪自动提醒。Apple Watch 先做 T36 真机技术验证，通过即可开发和送审；苹果正式放行前不对用户启用，会员页不宣传自动提醒。手机手动标记“我上头了”在两端独立提供，不要求连接手表。

## 后端（Go）

后端用 Go，初期做成模块边界清晰的单体服务，需要时再拆成微服务。采用云无关的容器部署。

- **框架**：Gin + oapi-codegen；OpenAPI 3 为接口契约。
- **数据存储**：PostgreSQL（sqlc 或 GORM）存用户、测评、画像；Redis（go-redis）做缓存、限次计数、配置变更通知；本轮不用对象存储，个人数据导出按需流式生成。
- **AI 调用**：国内主流模型大多兼容 OpenAI 格式接口，Go 直接调；需要框架可用字节开源的 Eino。
- **例外**：若后续自训语音情绪识别等模型，单独起一个 Python 推理服务，Go 通过接口调用。

| 服务模块 | 职责 |
| --- | --- |
| 用户与会员 | 登录、订阅、权益控制、AI 调用限次 |
| 测评 | WLEIS 计分、生成雷达图数据、四周复测 |
| 情绪识别 | 建立个人心率、语速基线；后端维护基线与阈值，手机区分本人波动和对话节奏 |
| 画像 | 维护用户和关系人画像，根据反馈修正 |
| 训练计划 | 按测评结果和画像排练习 |
| 模型网关 | 所有 AI 调用的统一入口（见下节） |

## AI 层：模型网关与自定义模型

业务代码只调模型网关、只写任务名（如“评分”），具体用哪个模型由网关按配置决定，换模型不改代码。主模型、备用模型和内容审核均须在国内处理和存储，不得出境。优先选择可签不留存或短期留存条款的服务商；准入要求见隐私清单。

1. **统一接口**：网关对内提供一套 OpenAI 格式接口，接新模型只加一个适配器。
2. **模型配置表**：每个模型存服务商、接口地址、模型名、密钥（加密）、单价。
3. **按任务路由**：角色扮演、回复建议、评分、画像推断、复盘分析、内容生成、简单分类各配主模型和备用模型。
4. **私有部署**：用 vLLM 部署 Qwen、DeepSeek 等开源模型，接入方式与云端 API 相同。
5. **微调**：本轮不将用户对练或复盘内容复制为训练集。
6. **兜底与监控**：主模型失败自动切备用；日志只留统计值和关联 ID，不复制原话或评分理由。
7. **提示词模板**：角色扮演、回复建议、按评分细则打分都写成带版本号的模板。

## 运营后台模型管理

换模型只由运营后台操作，用户不能自定义模型，因此不做用户级的模型配置和隔离。

- **模型列表**：添加、编辑、停用模型；密钥加密存储，后台只显示后几位。
- **任务路由配置**：给每类任务选主模型和备用模型，通过相同的数据条款准入后才可启用，不用发版。
- **灰度切换**：新模型先分一部分流量（如 10% 用户），效果没问题再全量。
- **提示词管理**：模板带版本号，可回滚，可与模型搭配做 A/B 测试。
- **监控看板**：按模型统计调用量、耗时、失败率、成本和评分结果分布。
- **热更新**：Go 服务启动时从数据库加载配置，后台修改后通过 Redis 通知各实例刷新，无需重启。
- **权限与审计**：改模型和密钥的权限只给少数管理员，所有修改记录操作日志。

## 隐私、安全与合规

原始录音只在手机本地分析、不上传，服务器只收音量、音调和单位明确的字符/秒语速等特征及时间点；转写正文和 PCM 不离开设备。特征可能混有对方声音，因此纯语音不用于自动认定本人情绪。

- **授权**：手表和麦克风都由用户主动授权，可随时关闭；提醒语气温和，避免被监控感。
- **加密**：情绪数据、日记、画像等敏感数据在本地和服务器上都加密。
- **生成式 AI 备案**：国内上线带 AI 生成功能的 App 需做相关备案。调用已备案模型要求相对简单；自己部署或微调的模型面向公众时要求更高，上线前需确认。
- **量表授权**：WLEIS 已获作者商用授权，授权函需归档。

## 收费模式与会员权益

采用免费基础版 + 会员订阅。价格参考国内同类订阅：月付约 20–30 元，年付约 150–200 元，最终按竞品和成本定。

| 权益 | 免费版 | 会员 |
| --- | --- | --- |
| WLEIS 测评与雷达图 | 有 | 有 |
| 每日小练习、知识卡片 | 有 | 有 |
| 聊天回复助手 | 每天限次 | 不限 |
| AI 情景对练 / 预演 | 每天限次 | 不限 |
| “我上头了”手动标记、个人标记历史 | 免费，不扣次 | 同免费版 |
| 手表提醒、录音与心率对齐回放 | 无 | 采集需单独授权，Apple Watch 自动提醒仅在 T36 放行后提供 |
| 按对象和场景汇总的个人情绪画像 | 无 | 有 |
| 文字复盘 | 每天 3 次 | 不限 |
| 关系人画像 | 1 个 | 有 |
| 个性化训练计划 | 无 | 有 |

同一用户从首次标记起 60 秒内重复点击只留一条；从标记继续提交 AI 文字复盘，成功后才计入文字复盘额度。免费版三个 AI 功能的限次为每天各 3 次；iOS 用苹果自动续期订阅，安卓第一版只卖一次性月卡和年卡，会员按内部用户 ID 两端通用；其他登录方式手动绑定，冲突不自动合并，iOS 内购以 appAccountToken 关联账号。定价要算进两项成本：大模型按用量计费，所以免费版必须限次；iOS 内购被苹果抽成 15%–30%。

## 开发顺序参考

T36 在 P0 用真机验证 Apple Watch 对话模式并准备审核材料；技术通过即可由 T31 开发和送审；上线须等正式放行。免费标记、历史和文字复盘入口由 T32A 与 P5 并行，不等硬件联调。

1. Flutter 主框架 + Go 基础服务（用户、会员、测评）
2. 模型网关 + 运营后台模型管理
3. AI 对练、聊天回复助手、复盘
4. 关系人画像、训练计划、成长档案
5. 手表心率采集、语音分析、情绪提醒

按 AI 会话拆分的开发任务见 docs/tasks.md。

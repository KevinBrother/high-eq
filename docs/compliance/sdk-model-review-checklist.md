## 1. 代码中的最低准入门槛

`provider_admissions` 表在数据库层要求：

- 处理国家为 `CN`、存储国家为 `CN`、`cross_border=false`；这些是项目方准入配置，不代表已取得法律或平台批准。`[已知：server/migrations/20261121000600_gateway_admission.up.sql]`
- 明确 `max_retention_days`、`deletion_method` 和非空 `terms_evidence`。`[已知]`
- 模型/审核服务必须绑定准入引用；未准入或准入被撤销时停用路由、解绑模型并删除凭据。`[已知：server/internal/gateway/management.go]`
- 关系人推断和审核服务的目标留存不超过 1 天，但固定基线只要求 `max_retention_days >= 0`，路由只比较主备/灰度相对留存；1 天绝对上限待实现/验收，不等于供应商已经满足。`[待实现/验收]`
- `ai_calls` 只保留模型、任务、提示词版本、耗时、token、成本、状态和必要关联 ID，不保存输入/输出正文。`[已知]`

## 3. 每个模型/审核槽位的必填证据

| 证据 | 要求 | 不能替代它的东西 |
| --- | --- | --- |
| 供应商主体 | 合同签约主体、统一社会信用代码或等效注册信息、地址和联系人 | 品牌名、模型名、销售个人微信 |
| 服务与版本 | 实际 endpoint、模型/审核版本、协议、固定版本策略和变更通知 | 官网宣传页、模型自述 |
| 处理地区 | 请求实际处理地、存储地、灾备地、支持/运维访问地 | 只填“全球”或“云端” |
| 跨境 | 是否存在境外处理、存储、支持访问或子处理者；如有，法律路径待律师判断 | 供应商勾选“无跨境”截图 alone |
| 留存 | 默认/可配置留存、日志留存、滥用监控、备份和删除 SLA | 供应商销售口头说明 |
| 删除 | API、后台或工单删除方法；删除证明、失败重试和离群副本 | 只有“支持删除”一句话 |
| 训练用途 | 是否用客户数据训练、微调、评测或人工审阅；如何关闭 | “不会使用”无合同条款支撑 |
| 子处理者 | 名单、地区、变更通知和同等义务 | 总合同中的概括授权 |
| 日志 | 是否记录 prompt、输出、账号、IP、设备、时间、错误；访问人和期限 | 只声明“不会泄露” |
| 合同/条款 | 合同、DPA、数据处理条款、安全附件、平台审核规则 URL、版本和日期 | 公开隐私政策截图 alone |
| 证据编号 | 文件哈希、归档位置、核验人、核验日期、有效期和复核日期 | 聊天记录或未签章草稿 |

## 4. 主备/灰度审核规则

1. **同一门槛：** primary、fallback、canary、moderation 和关系人推断模型均须有独立 `provider_admissions` 记录；不能因为备用模型只在小流量使用而豁免。`[已知]`
2. **同一字段：** 每个槽位记录实际发送字段、处理目的、处理/存储地区、跨境、留存、删除、训练用途和子处理者。`[待运营填写]`
3. **切换不等于新处理：** 路由切换、灰度百分比、模型升级、审核供应商更换和协议变更都要重新核验；旧证据不得覆盖新版本。`[待运营填写]`
4. **失败关闭：** 准入缺失、条款过期、处理地区不符、跨境未核验、留存超限或删除方法不明时，不得启用或继续路由。`[已知]`
5. **证据可追溯：** 每个真实调用应能追溯到模型配置、准入引用、提示词版本和调用统计；不得把输入/输出正文复制到调用日志。`[已知]`
6. **真实供应商为空：** 仓库没有预置真实供应商，不能用测试 fixture、`test.invalid` 或合成配置代替生产审核。`[已知]`

## 5. 与文案的对应关系

- 隐私政策中“我们使用 AI/审核/支付/登录服务”的每一句，都应有本表对应记录和证据编号。`[待运营填写]`
- 供应商未证明删除或留存时，不得写“聊天原文 24 小时内删除”“供应商不留存”“绝不用于训练”。`[已知]`
- 健康、语音、关系人推断和内容审核涉及敏感或他人信息时，应额外记录必要性、最小字段、访问控制、删除和真机/合同证据。`[待律师复核]`
- 供应商、子处理者、处理地区、留存或跨境发生变化时，应触发隐私政策版本、单独同意文案、应用商店材料和用户通知的复核。`[待运营填写]`

# T06 会员权益与限次

## 范围和入口

`GET /v1/entitlements` 只查当前登录账号。三个功能分别返回可用次数（已扣和仍有效的预占均不可用）及账号时区的下次重置时间；不限次用 `null` 而非大整数。策略在 `server/internal/membership/policy.json`，已支付订单的有效权益区间决定身份，不依赖设备或登录渠道。本卡不处理任何下单、续费或回调。

- **声明需要权限**：HTTP 操作使用 `appAPI.withRights(c, membership.Collection, fn)` 一类的事务包装；非 HTTP 调用在 `Accounts.WithSession` 或 `Data.Access` 的同一账号锁事务内使用 `Runtime.Membership.Require` 并执行业务操作。采集还要检查相应用途的 `accounts.Granted`，每次写入重新校验，不凭开始采集时的一次授权。`ManualMark`、`History` 不调用任何额度方法。手表自动提醒未启用。
- **关系人**：`RequireContact(..., nil)` 检查能否新增，传具体 ID 则检查能否继续使用。到期默认最近使用的一个可写，其余保留可读；用户明确改选调用 `SelectContact`，不要让浏览历史悄悄改选。
- **预占与生成**：先在账号锁内取得或创建同账号、同类型的 `activities` 根；以原 `session_id` / `request_id` 调 `Begin`。只有返回 `Work=true` 且事务提交成功的调用者才开始生成；模型调用在事务外。现有操作返回状态，不重新排队生成。保留服务端工作令牌，避免过期的工作者提交迟到结果。
- **成功**：整份输出明确通过审核才调用 `SaveApproved(ctx, tx, user, id, token, persist)`。`persist` 在传入事务中写可拉取的加密历史；失败必须回滚整个事务。首 token、已显示片段或网络 ACK 都不结算。对练只对首条审核通过的 AI 回复使用此方法，后续消息按 `client_message_id` 去重和落库；回复助手、文字复盘只在最终结果成功时使用。
- **结束与重试**：`Finish` 接收 `Completed` / `Exited` / `Failed` / `Safety` / `ModerationUnavailable`；已扣后正常完成或主动退出保留原扣，失败、危机或审核故障退到**原扣次日**。断网不调用 `Finish(Exited)`；重新连接读原会话。审核故障与危机提示不同，只有审核故障走显式 `Retry(..., previousToken)` 恢复，再按正常路径审核。T12 只返回评分结果，T19 在处理结果的事务内结算。

## 验证命令及实际结果

- `./server/tests/runtime.sh`：在只含本卡相关改动的临时副本上通过，使用隔离 PostgreSQL 17、普通 Redis 8.2 与独立删除登记。覆盖并发抵达、同一回复只保存一次、原日扣退、失败前退出、重连、会员到期与改选、普通 Redis 真停机/恢复、认证接口和冻结账号拒绝。
- 附加隔离验证：12 个独立并发请求只准入 3 个；删除成功操作并清除普通 Redis 计数后，日剩余仍为 0，手动标记和查看历史仍获准；午夜前预占不能挤占次日已满的额度；会员在预占与保存之间到期按保存时权益结算。跨账号不能结算他人的活动。
- `./server/tests/migrations.sh`：空库 up、SQL 约束、down 至空、再次 up 通过。迁移须按 `server/README.md` 在提交前相对 `origin/main` 核对。线上结果按本卡提交 SHA 查询 `T04 server`、`Migration history` 及仓库基础验证。

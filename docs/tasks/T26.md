# T26 · 成长数值副本、训练计划与每日内容

## 交付范围

本卡交付训练计划、题目与卡片、打卡/成就、成长评分投影及删除重算，不包含 T27 的界面。T19 关卡、T23 评分和 T25 关系人服务在同一生产运行时接线。下列验证使用虚构内容、合成账号和隔离存储；人工审题、真机和正式发布是独立条件。

## 已交付

### 评分副本与训练参考值

- practice 整场与 review 完整复盘通过 T03 同步事务事件接入；订阅者只收到 canonical decoder 从 `scores.detail_enc` 解出的四项 NVC、总分和三项情绪等级。
- 单项目 drill 不进入成长评分副本。源必须仍存在、归属当前账号、类型为 practice/review、状态为 `complete`，且原发生时间在 720 小时内、不晚于当前时间。
- `growth_scores` 只保存不透明 `score_id`、类型和分别按源绑定 AAD 加密的数值；日期与账号始终从现存源推导，理由、引文、改写和对话正文不进入副本。
- 按 `score_id` 幂等写入。账号隔离、重复投递、错误账号/活动/源、过期、未来、未完成和 drill 均由 T03/T04 原有查询边界拒绝。
- 成长参考值在账号事务内即时重算：最近一次 WLEIS 总分与 720 小时内存活 practice/review 的行为均值各占一半。新增或删除有效源立即改变分母，不持久化不可追溯的综合分。

### 测评后的计划生成

- 测评完成事件自动生成测评发生日的首份计划；`GET /v1/plans/today` 对尚无当日计划的历史测评做幂等补生成。
- 免费用户只按本人 WLEIS 最弱维度选择场景和题目，不读取任何关系人画像；会员权益校验通过后才调用受授权的 `ProfileProvider.AuthorizedScene`。
- 计划关卡通过 `LevelResolver.PlanLevels` 获取 T19 实际 Single/Full 关卡 ID；两者必须非空且不同，归档内不生成替代 ID 或回退 ID。
- 同一 assessment 的重复投递在画像与关卡读取前短路；`daily_plans(user_id,plan_day)` 是并发写入的持久化兜底。
- 最近 7 天已下发的题目与卡片不重复；到期 level 复习不会重置普通读人题的去重集合，只有显式复习题才允许复用。计划包含读人练习、单项关卡、完整对练关卡和知识卡片。
- 完成任一计划项即打卡；重复和并发完成保持幂等，并保留首次 `completed_at`。3/7/30 天成就按历史最长连续打卡天数计算，断卡不清空已达成成就。

### 单项进度与复习调度

- T26 使用独立的 `growth_drill_schedules` 数值调度投影，`activity_id` 外键级联源删除；T19 的 `drill_progress.progress_enc` 仍是完整单项历史的唯一来源，T26 不覆盖、不重写、不清空该密文或 `retry_at`。
- `DrillProgressed` 评分分档为 `0/5/9 -> retry_now`、`10/15/24 -> retry_in_three_days`、`25 -> pass`。
- 10–24 分以 `practice_work.completed_at + 72h` 设置重练时间，不以可能跨日的 `activities.created_at` 计算。
- 到期复习只挂到计划中的单项关卡项，并在加密计划内部保存精确源 drill ID。只有真实完成同账号、同关卡、同目标的单项练习才关闭旧排期；普通读人题打卡或另一账号的活动不能结清它。旧事件乱序补投只保留历史行，不复活 72 小时调度。重复完成保持幂等。
- 单项练习只记录过关进度，不产生成长评分副本，也不解锁训练参考分。

### HTTP 契约

- `GET /v1/plans/today`
- `POST /v1/plans/items/{id}/complete`
- `GET /v1/exercises/{id}`
- `POST /v1/exercises/{id}/answers`
- `GET /v1/cards`
- `GET /v1/cards/{id}`
- `GET /v1/growth`
- 冻结账号的全部成长业务读写均返回 401；尤其 `GET /v1/plans/today` 不得在冻结期间补生成计划。参数与依赖错误映射为 400/403/404/409/429/503。
- 题目详情不返回答案索引或解释；提交答案后才返回正确性与解释。卡片列表默认 20 条，合法范围 1–100，游标为上一页末尾卡片的 UUID。

### 隐私、导出与删除

- `growth` 已注册为 T04 必需隐私模块。`growth.json` 混合输出 `record_type:"score"`、`record_type:"plan"` 和 `record_type:"drill"` 三类显式记录。
- 计划导出不包含内部 `ReviewActivityID`，评分导出不包含理由、引文或对话正文。
- assessment 删除通过 `daily_plans.assessment_id ON DELETE CASCADE` 清理计划；sessions/reviews 删除通过评分、活动与外键级联成长副本和 `growth_drill_schedules`。
- 删除后重放不会重建评分、计划或单项进度；账号删除后同样由源外键级联清理。

### 内容

- `server/content/t26.yaml` 提供 50 道原创虚构读人题和 20 张知识卡片，覆盖 work/partner/family/friends/social 五个场景。
- 加载时校验数量、ID 唯一性、场景、题目、选项、答案索引、解释与卡片完整性；修改 YAML 不需要改调度代码。
- 内容来源已注明为合成材料且未经人工审核，不能据此宣称已通过内容签收。

### 本轮复审窄修复

- Runtime 的 practice/reviews/assessments 启动补投改为 best-effort：冻结或删除栅栏导致的单个账号失败只记录错误并保留 outbox，交给分钟任务重试，不再阻断整个 API 启动。
- 到期 level 复习不再清空普通读人题的已用集合；固定 2026-11-19/22 反例确认同一道普通题不会绕过七天去重，显式复习题仍可复用。
- 单项事件乱序补投不再吞掉真实打卡：旧事件按账号时区和真实发生日完成原计划，旧排期保持 `closed_at` 终态；重复投递幂等。已由真实关卡事件完成的 level 再次 `POST /complete` 返回当前进度，未完成 level 仍返回 `ErrInvalid`。
- 冻结账号回归扩展到待投测评重启和冻结后重新登录：服务正常启动、`completion_pending` 保留、`/v1/me` 可读、全部成长路由仍为 401，无关账号计划接口可用。

## T19/T23/T25/T27 合装复验

生产运行时直接以 T19 真实目录和 T25 授权范围配置计划服务，将测评、整场/完整复盘、单项进度分别订阅到相应处理函数。单项保持 T19 的 `drill_progress` 源密文不变：T26 的 `growth_drill_schedules` 使用独立的 `schedule_enc` 保存分值与档位，按真实完成时刻安排 10–24 分的 72 小时重练。低于 10 分只提示立即再试。结清后保留终态直到源删除，不让旧投递重新排期；答一道普通题不能结清复练。

父会话实跑了 PG17、普通 Redis、独立 AOF Redis 以及 Flutter 的真实 HTTP 路径。新建合成账号并提交测评后，可拿到当天计划、作答（缺少或 null 的 `choice_index` 返回 400，0 有效）、打卡，重建客户端仍读回同一进度。冻结账号的成长读写均被拒绝且不会借由 GET 生成计划。T23 的受控模型返回 NVC 20 和情绪 2/3/2，对应行为分 24；真实 T26 投递成功后，`GET /v1/growth` 的计数从 0 变 1，训练参考为 (WLEIS 百分制分 + 24)/2。删除该复盘并重投原事件，计数恢复为 0、无训练参考，内部导出没有该分数。事件投递中途失败的回归使用故障注入订阅者，不再用测试代码代写第二份 `growth_scores`。

上述为隔离组合证据，而非真实模型、正式发布或人工审题签收。50 道题和 20 张卡待项目方逐项审校。

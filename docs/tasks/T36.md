## 范围和入口

打开 [`watch/prototype/T36.xcodeproj`](../../watch/prototype/T36.xcodeproj)。手机与手表各有一个独立于生产的测试 App。手表显式同意后，以 `HKWorkoutSession(.other)` 和实时 builder 观察**本次**心率，用 `CMPedometer.currentCadence` 观察有效步频。不查询历史、不用 HRV，不把缺失步频计作静止。计数按不同的样本时间计算；不是对采样频率的承诺。

表端只在会话内存中显示最近的心率（次/分）与步频（步/分），结束即清空读数。手机只收到计数、时间和测试状态；配对链路不传生理读数。手机按钮是人工测试指令，不依赖心率，也不判断情绪。只用 `WCSession.sendMessageData`，不排队、不重试；过期（>5 秒）、未来、重复、乱序、旧连接或已结束会话的指令不触发轻震。手表结束时先使指令失效，停止步频和训练会话，丢弃 builder；不调用保存训练。这里的“不保存”指原型不保存训练或样本，不是删除系统自行生成的健康数据。

## 验证命令及实际结果

2026-11-21，从仓库根运行：

```sh
xcodebuild -version
xcrun swiftc --version
xcrun --sdk iphoneos --show-sdk-version
xcrun --sdk watchos --show-sdk-version
./watch/prototype/verify.sh
```

本机 macOS 26.7.3，Xcode 27.2 (27B52)，Apple Swift 6.4.2（语言模式 6）；iOS / watchOS **SDK** 均为 27.2。合成指令门控、采样时间去重、步频单位/缺失值及消息编解码检查成功；通用 iOS 设备无签名 Debug 构建成功，检查了内嵌 Watch 可执行文件、配对 ID、用途文案及后台模式。脚本临时目录退出即清理。未安装运行，不读取个人设备、证书或健康库。仓库现有 `Verify` 工作流不是 watchOS 真机测试。

## 未验证条件 · 项目方人工清单

**准备。** 只用自愿测试者与专用配对设备，不使用个人健康历史或正在进行的体能训练。项目方自行在本地为两个测试 target 配置开发签名，必要时在项目 Build Settings 中覆盖 `T36_BASE_ID`；保留 Watch 后缀、配对关系、HealthKit 能力及 Workout processing。选 `T36Phone` 和配对 iPhone 运行，确认测试 App 已安装在手表。测量时拔掉线缆、退出调试器；两端自动对时、开启手表触感，明确是否开低电量/常亮。原型最低 iOS 17 / watchOS 10，不等于已测版本。

每轮填：日期 ___；原型 commit / build ___；负责人 ___；iPhone 型号 / **实际 iOS** ___；Apple Watch 型号 / **实际 watchOS** ___；佩戴、网络、低电量、常亮、是否调试 ___。各行记录开始/结束、观察值、异常、复现次数和受控证据编号；目前所有行均**未测**。仅保留计数、时差、遮蔽读数后的界面和电量，不提交健康读数、姓名、序列号、签名或账号凭据。

| 项目 | 操作与要记录的结果 |
| --- | --- |
| 同意与拒绝 | 打开两端，不开始；点开始再取消，应无采集。分别拒绝训练、心率读取、运动权限后观察；拒读与无样本不能凭系统授权回调区分。未授权项不得伪造为有效数据。重新授权后必须显式开始。 |
| 前台两类信号 | 手表点「开始对话测试」→「同意并继续」，手机刷新。先静坐 2 分钟，再步行 2 分钟。分段记两路起止计数、最近样本时刻、最长相邻间隔；只在确有步频更新时记可用。无首样或不支持单列，不能以 0 步频通过。 |
| 锁屏 / 切后台 | 分别手腕落下熄屏、手表返回表盘、手机切后台、手机锁屏，各保持 2 分钟；另测双方同时后台。注明真实锁定、佩戴解锁与熄屏的区别。各段起止读快照，返回后刷新；计数增长、最大间隔、末样距现在、手机当时能否接收分开记。恢复后收到快照不等于后台持续送达。 |
| 手机往返与触感 | 手机前台，表前台及表后台分别点「发送一次测试轻震」各 3 次。记每次可达性、往返毫秒、手表调用计数变化、佩戴者是否在数秒内感觉到一次。回执不是触感证据；无回执亦不能推断从未震动。 |
| 断连与恢复 | 使两设备隔离（避免 Wi-Fi 仍可达），记录两端可达性；断开前发送一次，断开期间再尝试，等待超过 5 秒后恢复。观察 15 秒：不能补震；刷新后仅新按一次才允许新震。另做结束→重新开始，旧会话不能再触发。 |
| 结束 / 异常 | 正常结束及启动途中取消分别测。记末计数、末样时间，保持佩戴并走动至少 60 秒，手机刷新：计数不再变、按钮不可发、无新震。再试系统中断、退出重开：无自动重启；必要时在系统设置撤回权限后重测。 |
| 耗电 | 同一设备/亮度/连接/活动强度，不充电；空闲对照与显式采集各 30 分钟，至少两轮，低电量提前停止。两端分别记起止电量、时长、温度异常、丢样与系统终止。换算为百分点/小时，对照差另列；精度不足记不可判定。 |

**判定与签收。** 测试负责人先登记拟支持的锁屏/后台条件、可接受的样本间隙与相对耗电预算；用上述记录逐项对照。可重复获得实时两路更新、数秒内实际轻震、无旧震、结束可停且耗电可接受，才可签技术「通过」并注明适用设备/条件。缺证或尚无预算为「待验证」；已复现关键路径失败时记「不通过」、失败条件与复测负责人，不以缩短测试或假设样本补齐。

## 下一任务及注意事项

**审核材料草稿（不是批准）。** 发行负责人按实际送审版本核对权限文案、隐私披露和演示：这是对话期间的情商训练辅助，**不是运动训练或医疗诊断**。如实解释为何尝试 Workout processing、何时前后台运行、可能耗电、如何结束、不留训练及原型数据流。健康读权限只为本次心率；训练写权限用于开启临时会话、不写成一次训练；运动权限检验步频是否可用于排除运动。没有麦克风权限。不要把 `.other` 描述成运动场景或承诺平台接受这种后台用途。

演示顺序：展示两端初始页 → 取消一次并说明单独同意 → 开启并展示计数 → 锁屏/后台再恢复 → 发一次测试震动并对照佩戴反馈 → 断连重连 → 结束并演示不再采集。正式版若改为自动判定，须重新展示实际触发条件、数据用途与退出，不得用本原型的手动按钮替代；准备配对演示视频、实际版本/build、隐私说明、后台必要性和测试联系方式，由发行负责人决定是否提交并留存对应版本决定。

**门控。** 技术待验证/不通过时 T31 不开工；技术通过后，满足 T28 依赖即可交接 T31 开发、测试与送审，不等苹果先批准。正式版本未提交、审核中、未放行、撤回或版本证据不匹配时，均保持生产采集与自动轻震关闭，T17 不展示该卖点；失败则记录原因、关闭路径并复测/重审，不包装为健身绕审。免费 T32A 手动标记及其他无关功能不受阻。本卡不改生产开关、会员页或其他任务。

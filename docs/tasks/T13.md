# T13 · 运营后台脚手架、权限与审计

## 范围和入口

[本地启动与建号](../../admin/README.md)。Flutter Web 独立入口 `admin/lib/main.dart`，仅提供登录、工作台、审计查询；宽屏侧栏、窄屏底部导航。`operator` 不显示审计入口，手输 `/#/audit` 也不给数据。`super_admin` 可按操作人 UUID 和本地日期组合查询、重置及继续加载。请求失败可重试，退出须收到服务端确认（401 也清除本地会话）。

- 权限边界在 `server/internal/adminops/`，不在 Flutter。Gin 路由组先按**方法 + 路由模板**鉴权，再由生成的 adapter 绑定参数；未登记的操作默认拒绝。`operator` 直接 POST/PATCH/测试模型或 PUT 路由为 **403**，匿名、过期和 App 令牌为 **401**。T14/T15 未实现的方法，即使角色有权也只返回 **501**。生产装配入口为 `service.Runtime.Router()`。
- 没有默认密码、HTTP 注册或 App 账号复用。`cmd/admin-account` 只从 stdin 取密码，明文不落库；密码使用 bcrypt，后台令牌是 256 位随机值，数据库只存 SHA-256 摘要，8 小时后过期，退出撤销。每次请求从库取当前角色；Flutter 只在内存持有令牌，不持久化，也不放入 URL。
- 审计实现：写操作先插入独立尝试行，只含时间、操作人、固定 action、对象和结果。对象只取规范化 UUID、任务枚举或固定资源名，不从请求正文、原始路径或查询串提取。失败默认 `failed`、无权 `denied`，业务写入和标记 `ok` 必须在同一 PG 事务提交后才发送成功响应。匿名尝试、未识别账号和受信 CLI 建号使用全零 UUID 表示无已认证的管理员；已知登录失败归于该账号 ID，不保存登录名。审计表不关联 App 用户或用户源，不进入用户导出/删除钩子。列表按 `(occurred_at,id)` 倒序稳定分页，时间区间为 `[from,until)`。

### 审计按操作人与本地自然日（2026-11-26）

原有覆盖是两端分开的：`admin/test/workspace_test.dart` 只验替身 transport 下的筛选表单，`adminops` 集成用例在真实 PG 上验证操作人和半开时间但只经生成路由。本卡补“正式页面 + 真实 HTTP/PG”的正常读路径：具名 Go 用例 `TestT13AuditActorAndLocalDatePage`，构建标签 `integration && t13audit`，必须显式 `T13_DISPOSABLE=yes`，不在普通 `integration` 回归中运行；缺前置直接失败，不 skip。用例从自身源文件位置推导仓库根，经正式 `POST /admin/v1/auth/login` 登录合成超级管理员，再以正式 `/audit` 页面（`admin/tool/t13/audit_live_test.dart`）对真实回环 HTTP 输入一个操作人 UUID、用日期范围选择器选一个本地自然日并点「查询」。

以下命令均从仓库根执行。前置：Go 1.26、PostgreSQL 17（`initdb`/`pg_ctl`/`createdb` 在 PATH）、Redis 8.2、Flutter 3.38.10，且 admin 已执行 `flutter pub get --enforce-lockfile`（用例以 `--no-pub` 启动页面）。缓存 Redis 与删除登记 Redis 必须是两个独立实例。删除登记实例按启动器要求：`LEDGER_URL` 的 DB 为 0，首次绑定必须指向空库（DB 0 无键），并启用 `appendonly yes`、`appendfsync always`、`maxmemory-policy noeviction`、`no-appendfsync-on-rewrite no`、`aof-load-truncated no`；复用旧目录或不持久化会令 `Start` 拒绝启动。

```sh
REPO=$(git rev-parse --show-toplevel)
WORK=$(mktemp -d)                      # 新目录保证 ledger DB 0 为空
initdb -D "$WORK/pg" -U t13_local --auth=trust --encoding=UTF8 --no-locale
pg_ctl -D "$WORK/pg" -l "$WORK/pg.log" -o "-h 127.0.0.1 -p 55432 -c unix_socket_directories=" -w start
createdb -h 127.0.0.1 -p 55432 -U t13_local t13_audit

mkdir "$WORK/cache" "$WORK/ledger"
redis-server --bind 127.0.0.1 --port 56379 --save '' --appendonly no \
  --daemonize yes --dir "$WORK/cache" --pidfile "$WORK/cache.pid"
redis-server --bind 127.0.0.1 --port 56380 --save '' --appendonly yes \
  --appendfsync always --maxmemory-policy noeviction \
  --no-appendfsync-on-rewrite no --aof-load-truncated no \
  --daemonize yes --dir "$WORK/ledger" --pidfile "$WORK/ledger.pid"

export DATABASE_URL="postgres://t13_local@127.0.0.1:55432/t13_audit?sslmode=disable"
export REDIS_URL="redis://127.0.0.1:56379/0"
export LEDGER_URL="redis://127.0.0.1:56380/0"
export APP_ENV=development BACKUP_RETENTION_DAYS=45 PAYMENT_MODE=disabled DATABASE_POOL_MAX_CONNS=20
export FIELD_KEY_BASE64="$(openssl rand -base64 32)"
export WLEIS_CONFIG_PATH="$REPO/server/internal/service/testdata/t26_assessment.yaml"
export T13_DISPOSABLE=yes

(cd "$REPO/admin" && flutter pub get --enforce-lockfile)
(cd "$REPO/server" && go test -tags integration,t13audit -count=1 -run '^TestT13AuditActorAndLocalDatePage$' ./internal/service)
```

端口占用时改 55432/56379/56380 并同步改三个 URL。一次性 PG 中直接预置时间明确的合成审计行（固定普通 action/target/时间）：所选操作人在所选日的目标行、同一操作人在前一日的控制行、同一操作人恰在下一本地午夜的边界行、另一操作人在所选日的控制行。页面客户端按顺序记录真实 `GET /admin/v1/audit-logs`。点击前必须恰有一次初始化请求，且该请求不含 `actor_id`/`from`/`until`；测试在冻结测试时钟、指针释放后不 pump 的段内读取记录，要求「查询」按钮的释放事件本身恰好发起一次请求，随后等待期间不再出现额外 audit GET。服务端按序记录同轮请求，两端逐条相等且总数等于初始化加点击两次；`actor_id`/`from`/`until` 从该释放请求读取，不靠“全程最后一个”或延长等待推断。断言 `from`/`until` 恰是所选本地自然日的两个午夜换算成服务端时刻（同一 OS 时区；本次为 UTC+8，窗口 `[2026-11-24 16:00Z, 2026-11-25 16:00Z)`），且 `until` 为排他上界。随后按该点击后请求的 `[from,until)` 与操作人回查 PG，要求恰好命中所选目标行；把日期放宽到仅操作人应得 3 行、把操作人放宽到仅当日应得 2 行，因此漏掉任一筛选都会出现可区别结果。Flutter 按每个结果 `Card` 收集该行恰好三个可见字段（「结果 · action」「本地时间」「操作人 / 对象」），Go 与 PG 行按顺序逐行、逐字段比较，不按全屏文案计数。已验范围仅此正常授权读路径：未测分页/加载更多、重置、错误重试、operator 角色可见性、401/403、其他时区、真实浏览器、真实日志或个人记录，也未接供应商；未发现产品错误，未改动产品代码。

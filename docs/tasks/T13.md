# T13 · 运营后台脚手架、权限与审计

## 范围和入口

[本地启动与建号](../../admin/README.md)。Flutter Web 独立入口 `admin/lib/main.dart`，仅提供登录、工作台、审计查询；宽屏侧栏、窄屏底部导航。`operator` 不显示审计入口，手输 `/#/audit` 也不给数据。`super_admin` 可按操作人 UUID 和本地日期组合查询、重置及继续加载。请求失败可重试，退出须收到服务端确认（401 也清除本地会话）。

- 权限边界在 `server/internal/adminops/`，不在 Flutter。Gin 路由组先按**方法 + 路由模板**鉴权，再由生成的 adapter 绑定参数；未登记的操作默认拒绝。`operator` 直接 POST/PATCH/测试模型或 PUT 路由为 **403**，匿名、过期和 App 令牌为 **401**。T14/T15 未实现的方法，即使角色有权也只返回 **501**。生产装配入口为 `service.Runtime.Router()`。
- 没有默认密码、HTTP 注册或 App 账号复用。`cmd/admin-account` 只从 stdin 取密码，明文不落库；密码使用 bcrypt，后台令牌是 256 位随机值，数据库只存 SHA-256 摘要，8 小时后过期，退出撤销。每次请求从库取当前角色；Flutter 只在内存持有令牌，不持久化，也不放入 URL。
- 审计实现：写操作先插入独立尝试行，只含时间、操作人、固定 action、对象和结果。对象只取规范化 UUID、任务枚举或固定资源名，不从请求正文、原始路径或查询串提取。失败默认 `failed`、无权 `denied`，业务写入和标记 `ok` 必须在同一 PG 事务提交后才发送成功响应。匿名尝试、未识别账号和受信 CLI 建号使用全零 UUID 表示无已认证的管理员；已知登录失败归于该账号 ID，不保存登录名。审计表不关联 App 用户或用户源，不进入用户导出/删除钩子。列表按 `(occurred_at,id)` 倒序稳定分页，时间区间为 `[from,until)`。

## 验证命令及实际结果

- `cd admin && flutter pub get --enforce-lockfile && dart format --output=none --set-exit-if-changed lib test && flutter analyze && flutter test && flutter build web --release --no-web-resources-cdn`。独立 `Admin web` CI 固定 Flutter 3.38.10；组件交互覆盖两种角色登录、入口可见性、筛选及退出。本地分析零问题，2 个交互用例通过，release 构建成功；Chrome 打开本地静态包可见中文登录页。
- `cd server && go test -tags integration -count=1 ./internal/adminops`（仅在已配置 `DATABASE_URL` 的专用测试库执行）；`./server/tests/runtime.sh` 是等价的隔离 Compose 套件入口，CI 使用后者。测试通过生成路由发真实 HTTP 方法/请求体到 Gin、写读 PG17；覆盖普通运营 403、会话过期/撤销、审计的操作人/半开时间/分页、敏感字段排除与审计提交故障回滚。`TestPolicyCoversContract` 防止新增后台路由漏配策略。上述两个 Go 用例均通过。
- 真实 PG17 + 两个 Redis 8.2 下，`go test -tags integration -count=1 -run TestAdminIsolation ./internal/service` 通过：使用生产路由签发两套有效令牌，在各自命名空间读取为 200，互换均为 401。`go vet ./... && go test ./...`、`./server/tests/migrations.sh` 均通过（含 down 至空库再 up）。

## 未验证条件

本地 Chrome 检查只证明 release 登录页渲染；Flutter 交互测试替换 HTTP transport，服务端集成测试使用真实 PG 与合成账号。未接企业 SSO、二步验证、生产 TLS、生产网关限速或不可篡改的外部审计存档；本地 Compose 不应暴露公网。没有验证或提前开放 T14/T15 业务。

## 下一任务及注意事项

1. **加 API**：在 `docs/api/admin.yaml` 定义接口和示例；依 T04 生成 Go adapter，不手改 `routes.gen.go`。在 `adminops` 新文件实现生成方法，并在 `rules` 精确登记角色、固定 action/target 和开放状态；先测试 401/403、合法/非法输入以及拒绝时业务表不变，再开放。T14 模型/密钥/连通测试/路由写均仅 `super_admin`；T15 的提示词写允许运营角色。
2. **接写审计**：处理器用 `commitWrite` 传入的 `pgx.Tx` 做业务更新，自此事务内将当前尝试标为成功，不另开连接或提前发 2xx。T14 如果接网关自带提交的 `Catalog.Save`，应先拆出使用传入事务的保存原语，热更新通知放到提交之后；不要把两个独立事务称为原子操作。对不在 PG 内的外部连通测试，须保留尝试记录，再报告结果；不能把密钥、提示词、用户文本、上游错误串或完整请求路径加进审计。
3. **加页面**：在 `admin/lib/features/<feature>/` 实现视图；在 `core/api.dart` 封装同源 `/admin/v1/` 调用；在 `features/workspace/shell.dart` 注册命名路由及对应角色导航，桌面和窄屏入口一致。复用 `sessionProvider`，401 清会话，403 提示无权。更新交互测试覆盖手输路由、加载/空态、错误重试与真实服务端越权请求。

# T04 · Go 服务脚手架

## 范围和入口

当前开发入口仍是仓库根的 `./server/dev.sh`；脚本等到真实 `/v1/health` 响应含 `"ok":true` 才报告 Ready。[服务说明](../../server/README.md)列出端口、凭据与停机方式。原生入口在监听前应用内嵌迁移、连接 PG 与两套 Redis、绑定登记、构造账号服务并恢复未完成清理；T05 及后续卡已接入鉴权、账号和业务模块。实际开放范围要分开看：App 的生成路由先匹配操作，需要身份的操作先鉴权（可先返回 401），走到未实现分支才返回 `501 not_implemented`，未匹配路径由 `NoRoute` 返回 `404 not_found`；管理端另用 `adminops` 的 `guard` 和 `rules`，已匹配但缺策略的操作拒绝为 403。App 以 `internal/service/http.go` 的路由表和 `internal/service/runtime.go` 的模块注册为准，管理端以 `internal/adminops/http.go` 的策略为准。请求日志仅用服务端随机请求 ID、模块、结果及耗时，不记录请求路径、查询串、头、正文或底层错误。

以下描述只属于 T04 首版（历史）：`server/cmd/api` 启动前用 golang-migrate 应用内嵌迁移，连接 PG、普通 Redis 与独立 AOF Redis，核对登记并恢复未完成清理，之后才监听；两个生成包来自 T03 的 YAML；首版只有健康接口开放，鉴权尚未实现，任意 Bearer 字符串不会获得身份。

**新增一个接口**：改所属 `docs/api/{app,admin}.yaml` 的 operation、schema 和示例；使用 `go install github.com/oapi-codegen/oapi-codegen/v2/cmd/oapi-codegen@v2.5.1`，将 `$GOPATH/bin` 加入 PATH 后运行 `./server/generate.sh`。提交契约和生成结果，不手改 `.gen.go`。在 `internal/<模块>/` 实现用例，通过 `internal/service` 的 adapter 接生成接口。为已实现操作单独接入鉴权、授权和路由放行；不要直接移除全局默认拒绝。用 httptest 测正常、非法参数、匿名及越权，再跑真实服务测试。

**新增数据模块**：在 `internal/service/runtime.go` 的必需模块清单中声明模块名，传入同名 `privacy.Module` 的 `Delete` **和** `Export`，注册缺失、重名或分区名非法即失败。T04 首版时无上线业务模块（历史）；空清单不能成功删除/导出，今天的模块以 `internal/service/runtime.go` 的必需清单为准。新增独立删除源时，用新迁移扩展 `erasure_roots`、补齐 `privacy` 中固定作用域的删除 SQL，并核对级联子源、schema 和测试。内部清理键不同于外部会话/请求 ID；须在已认证账号范围解析，不能信任请求中的账号或跨账号查源。

- 数据读写与导出走 `Data.Access` 或协调器的专用方法。所有写入方先锁账号再锁源；钩子与订阅者使用传入的 `pgx.Tx`，不另开连接、提交或异步写入。`Fields.Seal/Open` 的 AAD 应绑定表、字段和不可变归属/行 ID。开发密钥只从环境解码；不接受生产环境走开发密钥。
- 源事务成功提交后调用 `Bus.Publish…`。发布同步返回订阅结果；失败由发布方保留原始 ID 和时间重试，无全局顺序或消息队列承诺。按[事件目录](../api/events.md)订阅，按源幂等。评分只接受仍存在、归属相符、已完整完成且从原始发生时间算未满 720 小时的 practice/review。源模块接入评分解码器，锁内从当前 `scores.detail_enc` 提取四项 NVC、总分和三项等级；订阅者只收到数值，不能拿到明细或信任投递方重写的值。T26 自己实现幂等投影及重算，不在脚手架计算训练分。
- `Data.Delete` 先在 PG 提交仅含根键的待办；另一个账号锁事务枚举相关源（含未评分活动），独立 Redis 原子登记并以同连接 `WAITAOF` 确认本地落盘后，才删除源、执行全部模块钩子并清待办。同一 SQL 事务内做副本清理和重算；钩子失败则全部 SQL 回滚。待办或独立登记命中时保守隐藏整个账号，避免聚合泄漏；登记不可用也拒绝处理。不声称 PG/Redis 支持跨库 ACID。按源重试，或在流量前运行 `Resume`；后者也检查只有 Redis 登记而没有 SQL 待办的旧快照。
- `Data.Export(ctx, request, writer)` 持账号锁流式写 ZIP，每个必需模块一个 `<name>.json` 数组；回调以 `emit` 逐条输出本账号允许的业务字段。模块或 writer 失败返回 error，不补 ZIP 结束目录。HTTP 接入时若已经发送字节须中断流，客户端不能把截断文档当成功。不落盘，不导出登记、密钥、他人数据。

## 验证命令及实际结果

- `./server/dev.sh`、`curl -i http://127.0.0.1:8080/v1/health`：从空库自动应用迁移，返回 `200 {"ok":true}`。
- `./server/tests/migrations.sh`：T04 首版时为 PG17 五组迁移做 up → 原 T02 约束/级联 → down 至空 → 再次 up（历史）；当前交付父按目录运行全部迁移（26 个 `*.up.sql`）做全量 up/down/up。
- `./server/tests/runtime.sh`：实际启动 Go 1.26、PG17 和两个 Redis 8.2.0。既检查 HTTP 就绪，也通过 `pg_blocking_pids` 观察两种先后顺序的实际锁等待；验证重复消费、拒绝过期或错源、删除后重投、注销前尚未评分的根、ZIP 内容及钩子失败回滚。检查独立登记为空值、45 天 TTL；故障后重试/恢复、仅有独立登记时的访问阻断与重删、失去登记库身份、错误逐出策略、登记与 API 重启后持久化、停止登记容器后的拒绝处理。
- `cd server && go vet ./... && go test ./...`：HTTP、事件、加密、配置、钩子注册。CI 单独的 `T04 server` 还按锁定版本重新生成代码并检查差异，运行 `go test -race ./...` 和同一真实服务脚本。按提交查询：`gh run list -w 'T04 server' --commit <SHA>`。
- 本次交接复核：离线编译 `./cmd/api` 为独立二进制，从空目录在本机 `127.0.0.1` 随机端口真实启动两次（TERM 后干净重启）；唯一 HTTP 请求为 `GET /v1/health`，均返回 `200 {"ok":true}`。未运行 Docker/Compose，未验证账户或业务接口。

## 未验证条件

未接生产 KMS、真实登录/支付。T04 首版时未接 T12 评分明细格式或 T26 算法（历史）；当前训练和复盘已接评分并写入评分明细，运行时把评分事件接给成长和计划服务，具体以 [T12](T12.md)、[T26](T26.md) 文档为准。本次原生二进制复核只证明开发态单机入口并只请求健康接口；未验证 Docker Compose、Linux/云、真实设备或 T34 恢复门槛。集成测试的源、分数及模块是测试夹具；PG 事务、锁、ZIP、登记库、停机和重启是真实执行。没有把登记命中演示当成云备份恢复验收：T34 须证明恢复点及独立登记的完整性与时效，在隔离环境完成全链路重删后才能开放。

## 下一任务及注意事项

T04 首版交接时的下一任务（历史）：T05 接认证和账号钩子；其他业务卡须先注册钩子再开放接口。T05 已完成，当前状态以 [T05](T05.md) 等对应文档为准。T30 单窗口不透明根及基线重算见 [CHANGES](../CHANGES.md)。T34 使用独立、不受缓存驱逐的登记卷与访问控制，部署前核实最长可恢复备份期；登记覆盖为 `max(30, BACKUP_RETENTION_DAYS)`。改变覆盖天数会拒绝原绑定，须停流量、先延长现存登记并核对可恢复窗口，再切换安装元数据和配置；不能清库重绑。T35 验收各实际分区内容、导出中断、单源/注销清理和重算。

# T21 · 聊天回复助手（后端）

在已包含 T19、T23、T25 的 `b197fab` 上合装。回复助手使用 T10/T11 的实际网关、T06 额度结算和 T25 关系人摘要；测试使用合成账号与受控上游，没有调用商用模型或采用用户聊天。运行验证与外部签收分列如下。

## 范围和入口

- `server/internal/replies/`、`internal/service/replies_http.go`；唯一 App 契约见 `docs/api/app.yaml`。`POST /v1/replies` 使用登录身份、非空聊天、可选目的/关系人。先走 `PUT /v1/me/consents/chat_import`；只读、外账号或不存在的关系人不能用于新生成。有联系人时在请求的账号事务内通过 `ProfileProvider.ForModel` 读取当前且获准用于模型的画像摘要；无联系人时摘要为空，不推断、不读取画像。
- 只走 T10 `reply_suggestion`、`JSONObject`，不设片段回调。T11 草稿 ID `ffa572d2-bc80-441d-a6ac-6c9e17b33e21` 不会自动发布。**输入先审，生成的整份 JSON 再审**；通过后校验字段、重复键、非空分析、2–3 个不同风格及理由。聊天与目的既保留完整规范化行，也保留去说话人标签后的正文；任一字段包含来源片段即拒绝保存：长度至少 4 字时比较所有 4 字窗口，长度不足 4 字时比较完整规范化来源；若规范化后为空（如 `？？？`），则以去空白原文作为来源，不允许标点-only 文本逃出逐字留存边界。因此 `合成暗号：` 这类冒号结尾文本即使被误判为标签、`？？？` 这类纯标点即使被归一化清空，也不会逐字留存。回复建议模型不能通过 `safety_flag` 自造危机；危机只能由独立审核或 `scoring` 任务的显式标志产生。业务只加自己的资源 ID。危机只返回契约中的 `{safety:true,message}`；审核故障为 `503 moderation_unavailable`、可用原 ID 重试，没有求助文案或模型输出。
- 幂等范围是 `(登录账号, request_id)`。输入指纹不同 → 409；同输入且处理中 → 202；已完成或危机 → 原结果；对应回复单删后原键重放 → 409。获 T06 令牌并提交预占后才在事务外生成；每次输入审核、主/备生成、输出审核的外部发送前，都在账号会话事务中复核与原操作绑定的 `chat_import` 授权记录。若使用关系人摘要，还须匹配原 `contacts` 授权记录及当前使用权；无关系人时不检查关系人名额。生成返回后、成功写入前再复核相同条件；生产 `routedDispatch` 把网关版本查询和真正 provider 调用放在同一个授权闭包内，数据库步骤复用该事务，不在授权事务持锁时借第二条连接。`DATABASE_POOL_MAX_CONNS` 默认 16，严格允许 1–256；单连接池回归覆盖授权事务内的版本查询。HTTP 断连不取消这个有界工作。正常结果以绑定账号、活动及用途的 AES-GCM 密文保存，**和成功扣次在同一事务**；重试不扣第二次。普通生成失败非危机，未取得可用结果不扣次，已终止的失败不会因轮询自动再生成。终态结算失败会以同一幂等令牌补偿重试一次；仍失败则返回错误并留给 T06 租约恢复，不伪装成功。进程宕机且未提交结果时，T06 租约到期可接替；不承诺厂商调用跨进程宕机恰好一次。
- 原聊天与目的只在本次请求内存中使用，**不存 24 小时再删，而是不持久化**。回复类 `chat_imports` 旧行在迁移时清除，SQL 触发器拒绝重新写入；不将请求发到队列、导出或日志中。该保证针对本服务，不等同厂商留存证明。T04 导出 `replies.json` 包含本人的可读结果及反馈，不含输入 MAC。`replies.DeletionKey` 在已认证事务中将外部 `Reply.id` 解析为内部根键；T35 交给 `Data.Delete(scope="replies")`。删除单条、关系人或账号均级联清掉请求、反馈、待投递项和关联调用日志；单条删除不是退款。
- `POST /v1/replies/{id}/feedback` 校验本人的成功答复、实际建议下标和当前关系人写权限。`index` 从 0 开始；`outcome` 只记录效果。可选 `self_report=overwhelmed|not_overwhelmed` **必须由用户明确选择**，不从效果文字或对方的情绪反推。相同提交幂等，同一来源重复提交不同的本人确认返回 409。选择、效果及确认一起加密。有 T25 时在保存反馈的同一事务登记原始确认。每分钟独立重放两条队列：明确本人确认检查来源和权限，在同一账号锁事务中调用 T25 `RecordActivity`、分发 `profile.feedback` 并清 `pending`；普通效果分发 `reply.outcome`（`feedback_id,user_id,source_id,source_kind,occurred_at`）并清 `outcome_pending`，生产订阅在账号锁/授权事务内调用 `ReadOutcomeTx`，再写 `reply_outcome_receipts`，不调用画像 recorder、不发 `profile.feedback`。回执只保存源键、原时间、建议下标和处理时间，不复制聊天、建议或效果正文。两队列独立扫描、独立清位，任一订阅者失败不会阻塞另一条。`ReadOutcomeTx(ctx, tx, event)` 按 `feedback_id/user_id/source_id/occurred_at/source_kind` 精确读取，重新校验本人、活动、`outcome_pending` 和关系人当前写权限，解密后仅返回建议 `index` 与效果 `outcome`。源/关系人/账号删除或只读时不得投递，删除后重投不得复活回执。

## 原请求与授权边界

一次新请求绑定账号、输入 HMAC 和当时有效的用途授权记录。如在审核和主/备模型调用之间撤回后重新同意，旧请求不能借新授予的权限继续外发或结算。已经提交的外部请求无法追溯撤回。用户仍可在本人有效登录下重读已经保存的原结果，这不会再次生成；源删除后同一请求键不再创建新活动。回复任务不带关系人时，即使免费关系人名额已用完，也按回复额度而非联系人创建规则判断。

`reply_requests` 与 `reply_feedback` 从迁移 `20261123000021` 起记录活动键、授权绑定、加密结果相关元数据及两类反馈；`20261123000022` 加入删除后的请求键，`20261123000023` 增加非画像反馈回执。三组迁移均在既有 T23 迁移之后。服务端拒绝把回复类输入写入 `chat_imports`。逐字对比只检查确定性的归一化文字片段，不证明模型永远不会语义转述原话，极短词也可能误拦；实际回复质量需要用准入模型评估。

## 外部待验与厂商复现实验

1. 使用**仅有新建合成免费账号**的隔离实例，代理/网关禁正文日志。由项目方在 T09/T14 确认国内处理/存储、不出境、删除时限、实际发送字段、资费；配置已准入生成主备和独立审核。各实际生成模型需通过 T11 发布上面的草稿。密钥由项目方在受控环境配置，不提供给脚本或会话。真实路由的网络可达性、模型契约合格率、建议质量、危机识别和厂家留存均未实测。
2. 把**测试实例**转发至本机回环端口，使用短时合成 App 令牌；脚本只接收端口和固定合成用例，不读聊天文件、厂商私钥、真实用户资料，不输出回复正文。避开额度重置边界，每组使用有余额的账号。
   ```sh
   ./server/tests/t21-vendor.py --synthetic-staging --port 8080 --case normal
   ./server/tests/t21-vendor.py --synthetic-staging --port 8080 --case safety
   # 只在专用测试环境暂时切断审核，保持生成路由不变；实验完恢复审核。
   ./server/tests/t21-vendor.py --synthetic-staging --port 8080 --case outage
   ```
3. 脚本核验契约、正常/危机重放及净扣。**HTTP 成功不证明使用了真实厂商。** 按脚本输出 `request_id` 和合成账号限定 `ai_calls.operation_id/user_id`，核对生成/审核模型 ID、实际提示词版本、时间、结果和厂商侧计量证据；对正常请求确认重放未增加尝试。由项目方在隔离端看合成建议，核对情绪/需求是可求证的猜测、不同风格、理由确能教思路。记录脱敏证据、真实厂商条件及实际通过/失败数量，不用受控输出顶替。厂商不支持或未提供材料的分支仍标未验；实验完按 T35 清除合成账号和有关测试记录。


项目方仍须对真实模型的建议质量、独立审核、厂商合同和实际删除留存取得证据。T35 通用用户导出/单源删除入口另行交付；本卡提供的是内部注册的模块导出和删除协调器生命周期，不等于所有权利入口或灾备已验收。

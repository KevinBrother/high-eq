### 4.4 源记录、评分引用、数值副本与日志链路

| 层级 | 固定基线字段/关系 | 含义与删除要求 |
| --- | --- | --- |
| 活动源 | `activities.source_id` | 随机清理键；删除活动后，关联评分、成长投影、调用统计和专项进度不得由旧事件回填。 |
| 评分源 | `scores.id = activities.source_id` | 评分记录通过该关系指回活动源，不是另造不可追踪的评分 ID。 |
| 评分明细 | `scores.detail_enc` | 引文、用户轮次、评分理由、改写和分项只在该 AES-GCM 密文中；不得复制到 `ai_calls` 或普通日志。 |
| 数值副本 | `growth_scores.score_id`、`nvc_enc`、`emotion_enc` | 只保存数值投影；随评分源级联，删除源后重算或清除。 |
| 业务操作 | `ai_calls.operation_id` | 串联同一次业务操作的主模型、备用模型和审核尝试；不能拿单次尝试 ID 代替业务操作。 |
| 单次尝试 | `ai_calls.id` | 区分主备/审核的每一次尝试，保留各自状态、耗时、token 和成本。 |
| 评分引用 | `ai_calls.score_id` | 仅成功评分尝试由 `LinkScoreTx` 补上评分引用；失败或审核尝试可为空，不得为它们补造评分引用。 |

- `daily_plans` 仅以 `users` 为级联根，随账号删除；`drill_progress` 外键指向 `activities(id,kind)`，随单项活动删除。两者不能合写成同一删除范围。`[已知]`
- 删除与导出验收必须沿 `activities` → `scores` → `growth_scores` / `ai_calls` 追链路，并保留 `operation_id` 与单次尝试 `id` 的区别。`[待 T35 对表]`

### 4.7 T22 提交分析前的本机分享草稿

- 新增事实仅基于已发布 `bc66e6e` 的三份原生代码；它不改变 `f60ace3` 的 SQL 42 项基线，也不是 T21 服务端已合入的证据。
- 目的和使用者：只把用户本人从系统分享菜单选中的纯文本交接给主 App，供登录后编辑并决定是否分析。分享扩展不联网、不读取剪贴板、不要求登录；未分析不上传，开始分析并提交前不上传。`[已知：bc66e6e]`
- Android：系统分享只接收 `text/plain`，文字保存在当前 Activity 的一次性内存；`take` 领取后立即清空，进程结束消失，不写磁盘，也不是业务 AES-GCM。`[已知：bc66e6e]`
- iOS：用户点“带入草稿”后原子写入 App Group `group.cn.higheq.highEq.reply` 下的 `Library/Caches/T22/incoming`；再次带入会替换 `incoming`。写入使用 `.atomic` 和 `.completeFileProtection`，是系统完整文件保护，不是业务 AES-GCM。主 App 启动、回到前台或收到可用通知时可先领取，领取不要求已登录；未登录时不显示正文，也可丢弃，登录后才可查看或编辑。实际领取时将 `incoming` 改名为 `claimed`，成功读取后删除。`[已知：bc66e6e]`
- 清理边界：iOS 的 10 分钟仅用于拒领，不保证到点物理擦除；App 未打开时没有定时器删除过期 `incoming`，会留到下次领取或后续清理。新分享始终写 `incoming`，不会被旧领取者误删。`[已知：bc66e6e]` `[待真机复核]`
- T21 服务端仍未合入，不能把本机草稿交接写成服务端原文不保存、删除闭环或供应商留存已完成。`[待 T21 对表]`

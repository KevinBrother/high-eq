# T10 · 任务路由、备用切换与调用监控

## 范围和入口

本卡只实现 Go 内部调用与统计接口，不开放 App 或后台 HTTP 路由。入口在 `server/internal/gateway/{router,moderated,store,statistics}.go`。从 T09 的 `runtime.StartGateway(ctx)` 取得 catalog 后，调用 `catalog.NewRouter(runtime.Data, stop)`，只把 `*gateway.Router` 交给业务方；关闭顺序仍为 catalog 在 runtime 之前。

- 调用 `router.Run(ctx, gateway.Call{Scope: scope, Task: gateway.Scoring, Mode: gateway.JSONObject, Messages: messages})`。`Scope.User` 必须取自已认证账号，`Operation` 是可重用的业务操作 ID；有活动、关系人、模板版本时传相应内部 UUID。路由先在 T04 账号锁内检查源归属及版本任务。七类 `Task` 值见 `CONVENTIONS.md`，业务不可传模型、端点或密钥。
- 每次读 PG `model_routes`。`SHA-256(账号 UUID 的 16 字节)` 的前 8 字节按大端取整数，模 100 的桶号小于灰度百分比时选灰度。桶固定，不按请求随机。每次外发校验 T09 准入和同一配置版本；灰度和备用除境内准入外，还须用途和删除方式相同、发送字段不增加、留存不延长。失准、缺价、用途类型错误的去向不参与分发。主服务失败、流截断或迟迟无内容 token，可在**未发过片段**且总预算未用尽时尝试一次合规备用；仅缓冲而未发的主模型内容会丢弃。
- 模型三个模式内部均以 SSE 接收，以首个非空内容片段（非 HTTP 响应头或 role 帧）计 10 秒超时；主备共享 60 秒生成链路总预算，审核单次上限 10 秒。JSON 模式仍发送 `response_format`，完整、通过审核且是对象才返回。使用 `stream_options.include_usage` 需实际服务支持，且 T09 的 `sent_fields` 明示该字段，否则不发送。
- 输入先审；流式按标点、换行分句，正常结束再处理尾句并审核全文。`Emit(ctx, event)` 必须同步、尊重取消；只有 `fragment` 可临时显示。`safety` 和 `moderation_unavailable` 是互斥终止事件，用 `event.Terminal` **替换**已显示片段，不再收片段或保存为成功回复。非流式消费同一 `Reply.Terminal`（危机：固定求助对象；审核故障：可重试技术错误，HTTP 接入时映射 503）。评分 JSON 的 `safety_flag:true` 也走危机分支。空结论、异常对象或超时不判危机。
- `Stop(ctx, scope, terminal)` 是必填的幂等终止回调：取消评分并释放占用或退回原扣次日。终止时无成功 `CallID`、回复或评分；即使事件写出失败仍调用 Stop。若收尾失败，返回终止对象**及**错误，业务需按同一操作补偿，不能据此继续生成或结算。成功返回也不代表已保存或已扣次；普通生成失败由业务按活动状态收尾。网关不自建账本。
- PG 每次生成和审核尝试各记一行，只有必要 ID、时间、结果、用量和金额；无已知用量用 NULL。`gateway.Metrics(ctx, pool, Filter{From, Until, Task, Model, PromptVersion}, emit)` 读左闭右开时间区间，按任务/模型/业务提示词版本聚合。`Calls` 含主备各次尝试，`Failures` 为非 `ok` 的次数；`KnownCostCNY` 是小计，须与 `Unpriced` 一起解释。`gateway.LinkScoreTx` 在源评分成功保存的同一受保护事务内关联成功尝试 ID，分布按源分去重，不读调用正文。`gateway.Hooks()` 已注册到 Runtime，导出和删除见 `schema.md`。

## 验证命令及实际结果

测试只用了合成账号、对话、价格及假上游。为隔离共享 checkout 中其他卡的未提交文件，整服务复验使用 `git archive HEAD` 加本卡改动的临时副本，不创建 worktree。

- `./server/tests/gateway.sh` 通过（PG17、Redis 8.2，`go test -race -tags integration`）。10 万个合成账号在目标 0/1/17/50/99/100% 时命中数依次为 0/1015/17263/50176/99037/100000；逐账号复算一致。`TestRoutingStore` 实测七条路由、拒绝条款更弱的备用、按模型与版本筛选、已知成本与未知用量、成功评分关联、本人导出及源删除级联。
- 故障注入覆盖 503、首 token 超时、总预算、首段后断流不拼接；危机、首段前审核超时、首段后审核中断分别断言事件序列和替换文案，返回中无成功评分或调用 ID，未扣/已扣两种合成余额净扣均为零。`TestRejectedReviewRetainsReportedUsage` 复现并修复审核返回非法对象时丢失已报告用量；失败尝试不保留响应正文。
- `cd server && go test -race -count=1 ./... && go vet -tags integration ./...`；`./server/tests/migrations.sh`（up → SQL invariants → down 至空 → up）；`python3 scripts/migration_history/check.py origin/main :index`。迁移以已发布版本为基准，不包含并行卡的 SQL。

- `./server/tests/runtime.sh` 在仅含 T10 的临时源码快照通过：服务启动迁移、受保护事务、删除登记重启持久性及依赖故障均已验证。

## 未验证条件

未触达任何真实模型或审核厂商；不把假服务结果当作对条款、真实用量/价格或危机识别质量的验证。Stop 回调的合成余额断言不代替 T06/T19 的持久化结算验证。

# T20 · 对练与预演界面

已与 T19 服务端、T25 关系人以及 T17/T18/T24/T32A 导航合装，基线 `ab5e039`。真实模式只访问项目 API，不直接访问模型厂商。下面的“实服”指一次性 PG17、两套 Redis、真实 HTTP/SSE 和受控 TLS 上游，不是生产或真机签收。

## 范围和入口

登录后从 **练习 → 对练与预演**（`/training`）进入。默认 `APP_ENDPOINT=mock`，示例关卡、角色回复和反馈均来自账号生命周期内的内存模拟，不调用模型、不代表实际评分或扣次。真实模式只通过 T16 的鉴权端点及 SSE 解码器访问配置的 App 服务；没有模型 SDK、密钥或直连厂商的路径。

- `app/lib/features/practice/lobby.dart`：复用 T18 的全局场景、关系人可用性及 T17 会员入口。支持难度 1–3、预演描述、续练历史；带关系人的创建/重练在提交前重新校验权限。首次真实练习告知对话与评分保留期；429 不自动购买，保留返回及免费入口。
- `repository.dart` / `demo.dart`：真实与模拟使用相同的页面接口。真实关卡、历史遍历契约分页；创建前把固定请求体暂存在 T16 的账号加密续答区，成功后立即清除。丢响应后点「恢复上次创建」，仍发原 `request_id` 和原输入；放弃本地请求不等于退出一个已创建的会话。创建成功的启动参数由服务端写入 T19 的 `activities.content_enc`，本人详情 GET 只要求有效登录会话和归属，不要求仍有有效的 `practice` 同意，按需取回；创建响应与历史列表都使用不含 `setup`、自定义正文或关系人 ID 的 `SessionSummary`，演示仓库遵循同一边界。
- `chat.dart` / `conversation.dart`：已保存消息与临时气泡分开。`fragment` 不结算；`reply_saved` 后 GET 原会话；`in_progress`、断流、页面重开均先读原历史，已保存则不再 POST，未保存只允许显式重试原 `client_message_id`。从历史进入时只带不透明会话摘要，详情成功后才用最新 `setup` 恢复关卡、关系人、场景、预演文本和 `previous_id`；详情不可得时保持只读，聊天页后续恢复成功也会重建对比与重练上下文。对比读取以页面生命周期、仓库身份和会话代数隔离迟到响应。发言或结束操作确认前保留账号隔离的操作记录，不自动补发。返回列表不会调用 `/exit`；只有确认「主动退出」才会退出，迟到帧不会重开输入。
- 危机立即用固定求助提示替换流中回复，不显示评分；审核无结论只显示「服务暂不可用，可重试」。评分阶段的安全对象与 503 也分开处理。失败、危机或审核故障读回服务端 `settlement`，区分未扣、已扣及退回**原扣次日**；读回失败不把未知当作退款成功。
- `result.dart`：单项只展示唯一目标、理由、该项得分和 `next_action`；整场显示 NVC 四项、总分、三维等级和理由、原句及改写。`target_turn` 从 1 起只数用户发言。主动重练才生成新会话 ID；重练前一场直接按 ID 取结果，从关卡列表重新开始则按历史顺序取同关、同模式上次已完成成绩。不同关卡或无前次不凑对比。自定义场景历史从本人授权详情按需恢复原始创建参数，同账号跨设备可继续重练；不从私密发言猜测情境或关系人。

## 授权、续答与删除

- 真实模式下，新建、恢复待创建请求和主动重练都先读取服务器当前的 `practice` 同意。无授权时解释对话和评分保留期；仅在用户明确同意后写 `v1` 再复读，拒绝或写入/复读失败不提交正文。已有授权按服务端的有效状态读取，不宣称校验了未来正式版本；使用关系人还需当前使用权与 `contacts`。
- 服务器保存加密启动参数。新建响应与历史列表用 `SessionSummary`，不提供 `setup`、自定义场景或关系人 ID。本人凭有效登录会话和归属可通过 `GET /v1/sessions/{id}` 获取详情和启动参数，该读取不要求仍有有效的 `practice` 同意；重练创建时才复核当前同意。客户端按确切的 `previous_id` 对比；新建重练只可指向本账号已完成、启动参数相同的上一场。GET 不把已删除的上一场当作仍可比较。真实 Flutter 按详情的扁平结构恢复，不从用户发言猜场景。
- 客户端创建前只把原请求放入账号的加密 `creating` 操作日志，以便响应未知时用原 ID 恢复；成功后清理，不另外保存每场的场景文本或关系人缓存。删除本人关系人后，其关联会话不能再通过详情或列表读取，无关会话仍在。设备离线期间的所有旧操作是否随其他设备立即清除，不作此承诺。
- 封顶不可继续发送；此前已有已保存的助手回复，仍能结束评分。封顶时的 `finish` 在收到最终评分、危机或失败前不会仅因先读回 `capped` 就丢弃。审核故障是技术错误，非危机；显式重试仅复用原命令。重复主动退出不形成嵌套退出，409 与先发生的审核故障交错时保留最早的 `send` 以按原消息 ID 重试。危机终态不可重试。

### 同关前后分数对比回环（本卡交接）

- 随仓用例：`server/internal/service/t20_same_level_comparison_integration_test.go`（构建标签 `integration && t20compare`）、`server/internal/training/t20_compare_level_fixture.go`（同标签的临时关卡夹具）与 `app/tool/t20/same_level_comparison_test.dart`。夹具只在该标签下追加一条同目标关卡，默认构建的产品目录不变。
- 工作目录与复做命令：先在同一卡片内 `app` 下执行 `flutter pub get --offline --enforce-lockfile`，再从 `server/` 执行：

go test -count=1 -tags integration,t20compare \
  -run '^TestT20SameLevelResultComparison$' ./internal/service

- 依赖：Go 1.26；`flutter` 在 `PATH`（本卡入口把卡片根目录的 `flutter/bin` 放在最前；接手者可用自己的 Flutter SDK，但需保证同一版本可用）；一次性 PG17 库（`initdb/pg_ctl/createdb/psql`）与两套独立 Redis。cache 实例关闭 AOF（`appendonly no`）；ledger 实例开启 AOF（`appendonly yes`、`appendfsync always`、`maxmemory-policy noeviction`、`no-appendfsync-on-rewrite no`、`aof-load-truncated no`）。角色、审核、评分上游均为回环 TLS 脚本，不访问供应商。缺少任一 disposable 开关、密钥、保留期或合成测评配置时用例失败，不转为跳过。
- 观测：`/practice` 挂载产品自身的 `PracticeHomeRoute`，向 `HomeShell` 传入非空 `content` 后真实渲染 `PracticeHomePage`；从 `PracticeContinueActions` 的「对练与预演」进入 `/training`。大厅、历史条目、结算和回到同一 `PracticeHomePage` 都走真实 Widget 路由；回执在所在 route 动画完成、结算滚动位置空闲后，由页面实际渲染的 `Text` 提取，并记录包围盒、视口内与可命中的布尔值。夹具流量记录列表读取、本场详情读取与前场详情 0 次；Go 另按历史列表复算大厅的“完成 + 同模式 + 同关卡”谓词，确认移除关卡条件会误选第二场的 25。日志中的三场分数和耗时均取运行时可回读值。
- 未验：不是真机、不是真实模型，也不是 T19 的真机 20 轮角色质量或供应商签收；分数由脚本化上游固定，不代表实际评分分布。安卓端不在本卡范围。

### 最终恢复顺序复验

历史条目先作为摘要展示；取得当前会话详情后立即恢复完整重练参数，不因上次得分的慢请求阻塞重练入口。在大厅已取回同一明确前场的成绩时，聊天页不再重复获取；前场失效或换账号不复用旧成绩。模拟历史夹具显式推进两帧之间的虚拟时间，避免在进入断言前超时。练习子集 32 项通过，全套 Flutter 137 项通过、2 项需独立回环脚本而默认跳过。本卡的实际 Flutter/T19 HTTP/SSE 回环另行通过。离线恢复回归使用 Widget 重建，不等于物理跨设备或真机杀进程签收。

### 断流后恢复同一会话取回已保存回复（`page-reconnect`）

- 随仓用例：`server/internal/service/t20_page_reconnect_integration_test.go`（构建标签 `integration && t20reconnect`）与 `app/tool/t20/page_reconnect_test.dart`。Go 用例启动 Flutter 页面测试；页面测试只连接该 Go 用例的回环 API。

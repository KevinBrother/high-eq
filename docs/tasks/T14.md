# T14 · 模型准入、模型配置与任务路由

## 范围和入口

- 超级管理员登录 Flutter Web，进入 **模型与路由**（`/models`）。先在「准入凭据」独立核实合同并登记用途、精确 HTTPS 基址、模型范围、发送字段、境内处理/存储、不出境、留存上限、删除方式和条款引用。登记不创建或激活模型；换条款建新凭据。撤销需确认：会停用并解绑关联模型，移除引用它们的路由，业务停止分发直至重新配置。
- 「模型」从凭据带入服务商、端点、用途；可新增、编辑、轮换密钥、设置输入/输出人民币单价（元/百万 token）、启停和测试。密钥读取只有后四位；历史未登记后缀显示未知，留空不轮换。换服务商/端点须另给密钥，避免把旧密钥送到新去向。在用模型须先切路再改去向或停用。探测不收正文、查询参数或临时端点，只发固定合成输入；持有配置与凭据共享锁至限时探测结束，绝不回显上游响应。
- 「任务路由」覆盖七类任务；各选不同的生成主/备、独立审核模型、可选灰度模型和比例。保存时在服务端按 T09/T10 重新核验：启用、有价、用途正确且已准入；主→灰、主→备、灰→备均不得放宽留存、增加字段或更换用途/删除方式。未配置不分发。无供应商默认值，无 App 端指定模型的参数。
- 契约：`docs/api/admin.yaml`；处理器：`server/internal/adminops/{admissions,models,model_routes,management}.go`；事务内网关原语：`gateway.Catalog.SaveTx`、`ProbeTx` 和 `gateway.ValidateRouteTx`。管理入口全部要求超级管理员。T13 中间件先记尝试，业务写入、目标标识及成功审计同一 PG 事务提交；回滚保留失败尝试。配置写在数据库版本行串行化；提交后才发 Redis 提示，丢通知仍由分发前 PG 版本核对刷新。探测本身是外部副作用，不能用数据库事务撤回。未实现任何提示词或看板功能。

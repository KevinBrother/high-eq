# T25 · 关系人画像服务

## 范围和入口

`server/internal/profile` 为 T25 业务，`service/profile_http.go` 接真实 T03 生成处理器。`Runtime.Start` 注册 `ProfileFeedback` 订阅、`profiles` 删除和导出钩子，并实例化 T10/T11 路由器；不需要外部账号来运行测试。

- **关系人**：`GET /v1/contact-questions` 下发 7 道稳定 UUID 的问题；`GET/POST /v1/contacts` 分页/创建；`PATCH/DELETE /v1/contacts/{id}` 编辑/删除；`POST .../activate` 明确改选，`GET .../summary` 可读历史画像。问答按题 ID 检查，受控选项和简短同义回答映射到行为线索，其他自由描述与「还不确定」不猜测。五个大五维度、分歧风格以及仅伴侣的亲密相处线索分别有把握度。保存称呼、场景与规范化选择的 AES-GCM 信封，不复制原答卷。
- **模型用摘要**：`Runtime.Profiles.ForModel(ctx, tx, user, contact)` 在新训练事务中检查本人、当前授权/名额，并记录真正选用的关系人。普通查看、读历史或刷新列表不改变最近使用者；实际发送消息在 `claim` 事务内经 `ForModel` 写入 `last_used_at`，建会话和 SSE 回执不写。T06 按有效会员区间判定：免费 1 人；到期默认最近使用，改选后交换读写权；续费自动恢复。正常单账户到期→保留最近使用→改选→续费的正常子项见 [T18 的「到期→最近使用→改选→续费正常旅程（2026-11-26，随仓验收）」](T18.md)；其中会员期真实发送对练消息的 real-use 版本已随仓为 `app/tool/t18/verify_selection.sh`（构建标签 `integration && t18selection`，`T18_DISPOSABLE=yes`），独立复核归档只作历史证据。禁止对只读对象训练、编辑、推断、反馈；隐私删除无需重新同意或续费。
- **可选聊天**：`POST .../infer` 在账号锁内复核 `contacts` 和 `chat_import`，网络调用在锁外，成功保存前再复核授权、名额和画像是否已被编辑。只发场景、选项与必要片段，不发送称呼或账号给模型。T11 模板 UUID `b935fb60-5a85-4c12-82c0-401afd649325` 是**草稿**，须为获准模型发布 `profile_inference` 后才能实际调用。T10 为主、灰度、备用及审核端过滤留存协议大于 1 天者。正常输出仅接受 7 个有界整数，不采纳自由生成的标签或总结。审核明确危机 → 统一求助响应，审核不可用 → 可重试 503，两者均不保存画像。不依赖 24 小时清理任务：原文从未写入数据库、备份、请求日志或导出，临时材料随请求释放；同一份材料不按提交次数叠加权重。
- **用户画像**：`GET /v1/me/profile` 只说是否已有明确本人的波动线索，不透露按人/场景的统计。`GET /v1/emotion-summary` 才走会员能力检查。`manual_count` 单列存活手动标记，`confirmed_self_count` 只计明确肯定的本人记录。人工标记、节奏、未确认或否定都不增加后者；本卡不实现标记 CRUD、不限制免费历史。本人事件读源模块的 `emotion.DecodeFeedback`，不从语速、引文或评分猜主体。
- **删除重算**：`Data.Delete(contacts)` 先登记删除意图，再级联相关活动、源评分、成长数值副本、可关联 AI 日志及反馈。新增证据表的源/账号复合外键、唯一键使删除活动、事件、关系人或账号都不会遗留下票。画像与分组读取时从剩余来源计算，不存无法撤回的总分。`profiles.json` 导出该账号的现存规范化选择、画像与明确反馈，不含聊天原文。T35 负责通用导出 HTTP；不要绕过协调器直接删业务表。

### 明确反馈格式

`POST /v1/profiles/feedback` 使用 T03 的 `source_id, subject, confirmed, contact_id?, note?`。认证主体来自会话。`confirmed=false` 或 `subject=conversation` 不作证据。关系人方向只接受相应关系人的具体行为选项/同义词；本人互动反馈显式注明「本人上头」或「本人没有上头」。省略 note 只可重用源上已有的明确事实；不能从没有方向的请求推断倾向。不保存 note 原话。T30 肯定/否定、核对时间与 ID 必须来自仍存在且未过期的源事件。

T21/T23 在源活动为 `complete` 且用户实际反馈时，在同一事务中 `Profiles.RecordActivity(ctx, tx, ev, observation, scene)`；提交后通过 `Bus.PublishFeedback(ctx, ev)` 发送以下键。中断后重投**原 ID 与时间**，不是再造一票。`source_id` 是 `activities.source_id` 或事件 ID，不是公开会话 ID。T30 使用自己的确认 outbox。只在订阅成功时应用。相同源、主体最多一票；冲突的新方向不能伪装成重试。

```json
{"feedback_id":"00000000-0000-4000-8000-000000000025","user_id":"00000000-0000-4000-8000-000000000001","source_id":"00000000-0000-4000-8000-000000000002","source_kind":"review","subject":"contact","contact_id":"00000000-0000-4000-8000-000000000003","occurred_at":"2026-11-21T10:00:00Z"}
```

`source_kind=reply|review|self_event`；事件 `subject=self` 不传 `contact_id`，分组对象从真实来源读取。每个维度按同方向票数 `n`、相反方向总票数 `m` 计算：`n>m` 时为 `n/(n+m+2)`，否则返回线索不足、把握度 0。这是线索一致度，不是心理测量概率。

## Sol 独立发现逐条核验

### 1. 撤回同意后旧推断仍可能外发/落库（确认）

- **确认**：旧实现只在请求开始和保存前读取当前 `chat_import` 授权，没有把请求绑定到开始时的授权记录。撤权后重新授权会产生新的授权 ID，旧请求仍可能通过保存前检查；网关也没有在输入审核、主模型、输出审核或备用模型每次外发前复核。
- **实现**：`profile_inference_requests` 以 `(user_id, request_id)` 绑定关系人、开始时的 `chat_import` 与 `contacts` 授权记录 ID、输入 SHA-256 和 `processing/complete/invalidated` 状态。每次 provider dispatch 前调用 `BeforeAttempt`；任一授权撤权、重授、请求状态变化或输入摘要变化都会把旧请求置为 `invalidated` 并返回 409。`gateway` 对 guard 错误做内部标记并在路由边界解包，避免被误判为可重试的审核/厂商错误。
- **外发覆盖**：guard 在输入审核、主模型、输出审核和备用模型各自真正 `dispatch` 前执行；备用尝试前拒绝时不会发出模型请求。输入审核前拒绝时零外发。
- **留存过滤**：`profile_inference` 只选 `max_retention_days <= 1` 的主、灰度、备用和审核端点；主端点不合格返回配置错误，备用/审核端点不合格则不进入该次尝试。
- **测试**：`profile/infer_test.go` 覆盖授权未变、撤权、重授、已完成、输入变化和 terminal reservation；`gateway/profile_attempt_test.go` 覆盖正常三次 guard/dispatch、备用模型前拒绝、输入审核前零 dispatch、输出审核前不 dispatch；`gateway/routing_integration_test.go` 覆盖真实存储路由下 `>24h` 主/备/审核端点的拒绝；`service/profile_integration_test.go` 的 `consent change invalidates in-flight result` 覆盖真实 PG/Redis 中飞行中撤权再重授后 409、画像不变、旧请求永久 `invalidated`。
- **残余边界**：guard 返回与 provider 真正开始网络写入之间仍有瞬时 TOCTOU 窗口，当前只保证“每次实际外发前复核”，不能宣称绝对无竞态；要完全消除需要厂商侧支持撤销令牌或同步确认，本卡没有该外部能力。

### 2. 非伴侣摘要泄漏伴侣专属线索（确认）

- **确认**：旧 `render` 先更新 `Summary`，再判断场景是否设置 `Attachment`；历史 axis 6 投票虽然不再进入 `Attachment`，仍可能进入 `Summary`，并被详情、模型摘要和 `profiles.json` 共用。
- **实现**：`model.go` 在计算计数和 `Summary` 前跳过 axis 6；场景改为非伴侣时，编辑路径也清空 axis 6 的答案与模型材料。
- **测试**：`model_test.go` 的 `TestNonPartnerOmitsAttachmentFromSummary` 直接断言摘要不含伴侣文案；`profile_integration_test.go` 的 `scene change hides historical partner attachment` 覆盖详情、模型摘要和导出三条读取路径。

### 3. 已完成聊天推断重放覆盖新证据（确认）

- **确认**：旧实现只把 `request_id` 作为网关 operation ID，每次重放都会重新读取当前画像、再次调用模型并替换 `Material`；A 完成后 B 写入相反方向，再以 A 的原 ID/原输入重试，会把画像改回 A。
- **实现**：完成请求记录为 `complete`；同一 `(user_id, request_id)` 重放直接返回当前画像，不再次调用模型。相同 request ID 但关系人或输入摘要不同返回 409；`invalidated` 请求不能重新激活。
- **测试**：`infer_test.go` 的 `TestReserveInferenceTerminalStates` 覆盖 complete/processing/invalidated、输入变化和关系人变化；`profile_integration_test.go` 的 `completed retry does not overwrite newer inference` 覆盖 A/B/A 重放、调用次数保持 2、重放返回最新画像、不同输入 409。

## 第二轮 Sol 独立发现逐条核验

本轮只处理 `build/t25/sol-review-round2.md` 仍列出的四个具体反例；上一轮三项不重复宣称，也不把上一轮真实 PG/Redis 通过当作本轮证据。

### 1. 两种必要授权与可用关系人外发前校验（确认，已修复）

- **确认**：旧 `BeforeAttempt` 只复核请求行和 `chat_import` 授权记录，没有在同一事务内调用 `s.write`；因此请求停在输入审核后、主模型派发前时，即使 `contacts` 已撤回或关系人已因会员到期变为只读，聊天仍可能继续外发。
- **实现**：`checkInferenceAttempt` 增加授权闭包，在请求行与 `chat_import` 复核通过后调用 `s.write`。`s.write` 同时检查 `contacts` 授权和 `Rights.RequireContact` 的当前可写关系人；`membership.ErrForbidden` 会把请求置为 `invalidated` 并返回 409，其他授权存储错误原样返回且不误标为授权变化。成功保存前仍重复同一组检查。
- **测试**：`TestInferenceAttemptRequiresContactsAndUsableContact` 覆盖 `contacts` 撤回、关系人不可写、授权存储临时错误；`TestProfileInferenceReviewRegressions` 的 `contacts withdrawal blocks dispatch` 和 `read-only contact blocks dispatch` 覆盖请求已启动但尚未派发时的两个 HTTP 反例，并断言未派发、画像不变、旧请求重放 409。

### 2. 客户端断连后同一请求 ID 重放（确认，已修复）

- **确认**：旧 HTTP 事务入口绑定 `c.Request.Context()`，失败清理也使用同一上下文；客户端断开后清理事务无法开启，已提交的 `processing` 预留行会永久存在，后续同 ID、同输入只能返回 202。
- **实现**：`profile.Session` 改为携带 context 的事务入口；HTTP 入口显式把清理 context 交给账号会话。失败/终止清理使用独立的 `privacy.Coordinator.Access` 入口，不依赖原登录会话；它保留隐私删除屏障与冻结检查，并使用 `context.WithoutCancel` 加 10 秒 deadline，既不受请求取消影响，也不会无限挂起。普通失败仍返回原错误；终止结果优先于伴随错误。
- **测试**：`TestSettleInferenceRunDetachesCleanupFromCancellation` 实际断言取消后的清理 context 无取消错误且有 deadline；`client disconnect releases reservation for retry` 覆盖真实 HTTP 路径下预占已提交、客户端取消、清理删除预留、同 ID 重试成功和最终 `complete`。

### 3. 新建但从未使用的关系人不抢占默认名额（确认，已修复）

- **确认**：旧创建 SQL 写 `last_used_at=clock_timestamp()`，而 T06 默认关系人按 `last_used_at` 选择；新建未使用的关系人会在会员到期后抢走默认可写名额。
- **实现**：创建关系人时写 `last_used_at=null`；只有显式 `Choose`/`SelectContact` 或实际使用路径更新最近使用时间。新建行为不再改变默认对象。
- **测试**：`TestCreateContactStartsUnused` 直接断言创建 SQL 不含 `clock_timestamp()` 且写入 null；`unused new contact does not take default` 覆盖先使用 A、再创建 B、到期后 A 仍为默认可写、B 只读。

### 4. 网关终止对象与错误同时出现（确认，已修复）

- **确认**：T10 `Router.finish` 明确允许返回 `Reply.Terminal` 和错误；旧 T25 先处理错误，导致危机统一求助对象或 `moderation_unavailable` 503 被通用错误路径吞掉。
- **实现**：先判定 `reply.Terminal`，再做失败清理；终止结果不因清理失败或伴随的审核/审计错误变成通用 500。危机返回统一 `safety` 对象，审核不可用由 HTTP 映射为可重试 503；两种情况都不保存画像。非终止错误仍保留原失败与清理错误。
- **测试**：`TestSettleInferenceRunKeepsTerminalSemantics` 覆盖 crisis + audit error、moderation_unavailable + audit error、crisis + cleanup failure；`terminal replies survive accompanying errors` 覆盖真实 HTTP 状态、统一文案、画像不变和预留清理。
- **残余边界**：终止清理若真实数据库持续不可用，预留行仍可能保留；本卡只保证请求取消不会导致清理自身失效，数据库恢复后的孤儿行处理需要项目方在真实存储上验收。

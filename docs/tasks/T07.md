# T07 · 支付与订阅

## 范围和入口

本卡覆盖 T17 调用的六个既有 OpenAPI 操作；不改客户端、生成代码、T05 身份策略或 T06 权益读取。入口为 `server/internal/service/payments_http.go`、`server/internal/payments/` 及 `*_payment_ledger` / `*_checkout_cache` 迁移。

- **Apple**：`POST /v1/purchases/token` 返回当前账号稳定的 `appAccountToken`；禁用时在唤起 StoreKit 之前失败。`/purchases/restore` 验 StoreKit 2 交易 JWS；`/payment-notifications/apple` 独立验证 V2 外层和内层签名。核对 ES256、指定可信根和证书用途、bundle、部署环境、订阅 SKU、时间和 CNY 金额。Production 通知的 `data.appAppleId` 必须匹配数字 App ID；单笔交易用签名中的 bundle 和 environment 核验应用，不要求单笔 JWS 包含通知特有字段。token、原交易链和订单归属不能改写，异账号恢复返回 409 并提示验证原账号。
- **安卓**：`POST /v1/purchases` 接受月/年和微信/支付宝，不接受商户、金额、目标 URL 或回调地址。T05 会话锁内先提交 pending 单，再按同一账号检查、准备渠道参数。预下单超时或应答验签失败均不授予权益；重试原请求沿用相同 `out_trade_no`。pending 单五分钟内复用 AES-GCM 密文缓存的参数，入账/退款清空；过期缓存不可读，不承诺后台定时物理清除。成功返回 T17 的微信七字段 JSON 或支付宝 SDK 订单串，SDK 返回不是开通凭证。
- **回调与权益**：`/payment-notifications/wechat` 先验原文，再用 APIv3 密钥解密；`/payment-notifications/alipay` 验完整表单及收款主体。匹配渠道、商户、原订单、交易和金额，成功提交才分别 ACK 空 200 / `success`。已验证时间而非抵达顺序决定生效、续订、过期和全退；重复通知不重复授予，退款后迟到成功不复活。同账号退款/续订都重算 T06 的半开区间：安卓仅消耗 iOS 未覆盖的时间。账号注销删除明细/权益、订单脱敏保留；`payments.json` 不含票据、支付参数和内部 HMAC。

### 合并前复查：渠道接线

**已接入启动配置，不依赖测试代码注入。** `LoadConfig` → `paymentChannels` → `payments.Configure`。`PAYMENT_MODE` 未设置或 `disabled` 时不读取任何支付材料；否则用逗号选择 `wechat`、`alipay`、`apple-sandbox` 或 `apple-production`（苹果二选一）。任一已选渠道不完整、重复或无法识别时整体启动失败，不降级为假通道。进程由部署系统单独注入下列值；不是文件路径，不向仓库/客户端写入，不能通过订单 API 覆盖。

| 渠道 | 必需进程配置及协议边界 |
| --- | --- |
| 安卓共用 | `PAYMENT_NOTIFY_BASE` 为商户控制的 HTTPS origin（无凭据、路径、查询或片段）；服务端追加 `/v1/payment-notifications/{wechat,alipay}`。`PAYMENT_MONTHLY_FEN` / `PAYMENT_YEARLY_FEN` 为服务端正整数分，卡时长 30/365 天。 |

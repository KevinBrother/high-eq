# T22 · 聊天回复助手界面

## 范围和入口

- **实战 → 回复助手**（`/replies`），或从系统文字分享进入。未登录沿用 T17 登录页，不展示分享正文，可丢弃草稿；登录后仍需手动点「开始分析」。切换/退出账号时丢弃旧界面、草稿和结果。不开键盘监听、不读剪贴板、不读取源 App、聊天数据库或文件 URI。
- `app/lib/features/replies/`：首次导入单独说明含他人信息、用途与服务端原文保留期，通过当前账号 `chat_import` 授权后仅解锁提交；同意本身不发送文字。关系人与 T18 共用名册，只列可用项；可不选。粘贴/改写、选关系人、填目的均不触发分析。
- 一次操作冻结请求体及 `request_id`。超时、断线、202 和审核故障均可手动用原请求查询/重试；改变输入才开始新操作。**非流式**：HTTP 状态、完整 JSON、分析字段、2–3 条不同风格的建议和理由全通过才显示。202 只接受本次 ID；危机仅显示固定求助卡，审核故障仅提示「服务暂不可用，可重试」，不回显异常正文；空/畸形结果不拼凑卡片。逐条复制不发送到聊天 App，效果反馈仅提交用户明确选中的零基下标及效果，不推断本人情绪。
- **Android**：`ReplyShare.kt` 接收 `ACTION_SEND` / `text/plain` 的 `EXTRA_TEXT`，冷启动与 `onNewIntent` 共用一次性内存交接。**iOS**：嵌入 `ReplyShare.appex`，系统分享面板点「带入草稿」后，手动打开对话手记；扩展不唤起宿主、不联网。两端共用 `cn.higheq/reply-share` 的一次性 `take`。iOS App Group `group.cn.higheq.highEq.reply` 的受保护 `Library/Caches` 只放最近一条；领取时原子移出并删除，超过 10 分钟拒绝领取。未打开 App 时不承诺定时物理删除。Flutter 不将原文落盘。

## 第一轮审查修复（逐条对应 `build/t22/sol-review.md`）

1. **规范化输入不换 ID**
   - `page.dart` 的 `_draft()` 与发送组包使用同一套 `trim()` 规则；`edited()` 比较规范化后的 `chat_text`、`goal` 和 `contact_id`。
   - 仅改变正文/目的首尾空白时保留已冻结的 `operation` 和 `request_id`；只有规范化内容变化才清掉旧操作。
   - 400/409 设置 `mustEdit`；之后仅改空白仍保持禁用，必须修改规范化内容才能重新提交。
   - 回归：`page_test.dart` 的「仅改首尾空白时复用原请求 ID；真实内容变化才换 ID」和「409 后必须修改规范化内容才能继续」。

2. **活动关系人权限变化**
   - `ReplyCards` 接收本次操作的 `contactId`；初始化和每次反馈提交前都重新调用 `repo.contacts()`，该仓库只返回当前可用关系人。
   - 关系人消失、变为只读或权限查询失败时关闭反馈入口，不发送反馈 POST；服务端 403 也关闭入口并提示权限已变更，不再鼓励盲目重试。
   - 回归：`page_test.dart` 的「关联关系人变为只读后关闭反馈入口且不发送 POST」。
   - 边界：检查与 POST 之间仍有竞态；最终以 T21 服务端 403 校验为准，不把客户端检查说成原子授权。

3. **热分享后导航与原操作**
   - `ShareHost` 增加 `onWarmShare`；已登录收到新分享时由 `main.dart` 向现有 `Navigator` `push` 新页面，不通过 `revision` 重建整个 `MaterialApp` 导航栈。
   - 关闭热分享页时 `pop` 并 `discard()`；原页面、原 `request_id` 和「查看原请求结果」保持。`_selectNavigator` 只在 scope/status 类型变化时更换 Navigator key。
   - 回归：`entry_test.dart` 的「登录后热分享压入新页面，关闭后保留原请求与 202 操作」，使用真实 `HighEqApp`、导航栈和 MethodChannel。

4. **409 / 429**
   - 409 显示「本次请求与原操作不一致，请修改输入后再分析」，并设置 `mustEdit`，禁止原样重试。
   - 429 不依赖错误正文中的时间：调用 `GET /v1/entitlements`，读取 `allowances` 中 `feature == 'reply'` 的 `remaining` 与 `resets_at` 后显示真实剩余次数/重置时间；查询失败时保留不编造时间的兜底文案。
   - 回归：`page_test.dart` 覆盖 409、429 成功查询和 429 查询失败；`wire_test.dart` 覆盖 `GET /v1/entitlements` 的 `feature=reply` 解析。

5. **可选 `self_report`**
   - `ReplyRepository.feedback` 增加可选 `String? selfReport`；默认 `null` 时不把字段加入反馈报文，只有用户显式选择才发送。
   - 结果卡单独展示「本人当时的状态（可选，不会从效果文字推断）」，默认「不填写」，可选「本人当时上头 / 没有上头」。
   - 回归：`wire_test.dart` 断言默认报文不含 `self_report`、显式选择才发送；`page_test.dart` 断言默认不选和显式选择；`live_test.dart` 在真实 T21 合成服务入口中显式发送一次。

## 第二轮复审阻断修复（逐条对应 `build/t22/correction-geyktjwk/review.md`）

1. **P1 · 未登录冷分享登录后无法关闭草稿**
   - `main.dart` 的冷分享 `/` 根路由关闭回调先调用宿主 `close` 清除待登录草稿，再 `pushReplacementNamed('/assessment')`；热分享仍向原导航栈 `push`，关闭时 `pop` 并丢弃本次分享，不重建或销毁原操作。

   - 观察到的 RED → GREEN：修复前仍停留在「回复助手」并可见分享正文；修复后回到「是否同意开始本次自评？」且正文消失。

2. **P2 · 关系人在分析提交前降权仍发送正文**
   - `page.dart` 在已关联关系人时，于分析 POST 前重新查询当前可用名册。关系人消失时清空 `contact` 与旧 `operation`、设置 `mustEdit`；名册查询失败时清空旧 `operation` 并 fail closed。两种路径都不发送聊天正文，也不复用旧请求。
   - 回归：`page_test.dart` 的「关联关系人分析前降权时不发送聊天正文」断言 `analyze` 调用为空；额外增加「关系人权限查询失败时分析前不发送聊天正文」，覆盖权限查询异常时同样不发送。
   - 观察到的 RED → GREEN：修复前关系人消失后仍产生分析调用；修复后 `calls` 为空并提示修改输入。权限查询失败反例同样由非空调用转为零发送。
   - 边界不变：检查与 POST 之间仍有竞态，最终授权以 T21 服务端 403 为准。

3. **P2 · 非契约 HTTP 500 被误判为分析已终止**
   - 删除「不可重试的 500 视为终止结果」特殊分支。非契约 500 统一保留原 `operation`/`request_id`，显示「连接未完成，可用原请求重试」，使客户端可用同一请求取回可能已保存的结果。
   - 回归：`page_test.dart` 的「非契约 500 不把结果误判为终止，可用原请求重试」断言不显示「本次分析已结束」，第二次请求与原请求体完全相同。
   - 观察到的 RED → GREEN：修复前缺少「连接未完成」且重试入口被隐藏；修复后原请求可直接重试。

4. **P2 · 反馈 409 仍提示可重试**
   - `result_cards.dart` 将 409 视为本人反馈的终态：设置 `saved = true`，显示「该回复已有反馈记录，不能再次提交。」，并关闭提交入口；`saved` 分支显示该终态错误而不是默认成功文案。
   - 回归：`page_test.dart` 的「反馈 409 提示已有记录并关闭重试入口」断言终态文案存在、无「可重试」提示且提交按钮消失。
   - 观察到的 RED → GREEN：修复前缺少「该回复已有反馈记录」并仍显示提交入口；修复后入口关闭。

## 第三轮复审窄修复（对应 `build/t22/correction-geyktjwk/review-followup.md`）

本轮只处理最新复审剩余的两个阻断，不改变已关闭的入口、授权、反馈和结果展示边界。

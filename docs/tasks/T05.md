# T05 · 用户与认证

## 范围和入口

`server/internal/accounts` 实现 App 契约的 12 个操作：发码、登录、刷新、退出、冲突后切换、查阅/更正账号、绑定、申请/撤销注销、列出/更改当前授权。`internal/service/accounts_http.go` 适配生成接口；未实现的 App 操作和管理员身份未因此放行。本卡不做会员、付款或 T35 的导出页面/HTTP 端点。

- **注册和归属**：仅以已验证的 `(provider, subject)` 识别身份；手机号要求 E.164。首次须显式确认 14 岁及当前两个版本（开发契约 `2026-11`）。绑定提交 `current_proof`（当前账号任一绑定方式的**新** `Credential`）和新方式的 `credential`；注销的 `proof` 同样是完整 `Credential`，不是访问或刷新令牌。绑定 409 后不请求即保留当前账号，选择切换才用新凭据 `POST /v1/auth/switch`；不迁移任何权益/数据。
- **令牌与验证码**：访问 JWT 有效 15 分钟；校验算法、签名、签发方、受众、到期和服务端会话。256 位随机刷新令牌有效 30 天，数据库只留摘要；轮换和退出使对应旧访问令牌也失效。验证码 5 分钟、最多 5 次输入，60 秒一次、上海自然日最多 10 次。验证码消费和并发限流由 PG 行锁协调。
- **注销**：冻结即撤销所有设备的旧会话，业务读写、导出及评分消费拒绝冻结账号。15×24 小时内重新登录后，可读取 `/me` 的 `frozen_until` 并显式 `DELETE /v1/me/closure`；单纯登录不撤销。期满后不可恢复。启动监听前及每分钟调用 `PurgeDue`，走 T04 删除登记和全部模块钩子，失败重试不解冻。清理在写入不可逆的删除待办前，持账号锁复核截止时间，避免误删正在撤销注销的账号。订单保留匿名记录。客户端申请前需提醒在苹果设置取消订阅。
- **隐私**：`accounts` 注册成对钩子。`accounts.json` 只写本人的账号业务字段、解密后的绑定和同意历史，不含会话、OTP、摘要、删除键或服务端密钥。与账号级联的绑定手机号同时清掉发码状态。

**开发联调**：`./server/dev.sh` 后以测试号码调用 `POST /v1/auth/sms`，开发模拟码 `000000` 也必须已申请、未过期且未用过。Apple/微信用一次性开发票据：

```sh
ticket=$(uuidgen)
./server/dev.sh exec -T cache redis-cli SET "dev:ticket:apple:$ticket" fictional-person EX 60
# 将 ticket 作为 credential.proof；每次重新验证另生成一张票。
# 微信改用 dev:ticket:wechat:<ticket>。两个 provider 的 subject 空间彼此独立。
```

票据只通过私有开发 Redis 预置，无对外签发接口。不要向模拟器输入真实手机号或第三方令牌。

## 验证命令及实际结果

- 本地在隔离 PG17 / Redis 实跑 `go test -tags integration -run TestAccountLifecycle ./internal/service`。CI 入口 `./server/tests/runtime.sh`：隔离 PG17、Redis 缓存及独立 AOF 删除登记；包含 `TestAccountLifecycle`，通过真实路由和存储检查跨设备身份、双方重新认证、冲突保留与切换、短信窗口、令牌轮换/退出、冻结恢复和到期删除。删除前读取账号 ZIP，删除后拒绝再次导出及旧评分消费；检查源评分、成长副本、关联调用记录均已清除，订单归属变为 NULL。
- `docs/CHANGES.md` 的 **T16 → T05**：`TestAccountLifecycle` 对 health 先授权 v1、撤回，再授权 v2，每次用 `limit=1` 遍历所有页；每个用途只有一个当前决定，撤回后的决定仍可见。同一事务核验采集许可；其他用途和另一账号不变。ZIP 中保留该用途两段历史。
- `./server/tests/migrations.sh`：空库 up、约束、down 至空、再次 up。`cd server && go vet ./... && go test -race ./...` 检查令牌及环境拒绝路径。`scripts/check_contracts.py`、`app/tool/generate_api.py --check` 和 Go 生成器覆盖契约。按提交 SHA 核验 `T04 server`、`Verify`、`Migration history`、`Mobile scaffold` 工作流。

## 未验证条件

未发送真实短信，未用私人账号登录，未验证供应商、Apple 真机或微信开放平台。仅 `APP_ENV=development` 可装配假供应商。生产还需 T04/T34 的 KMS、独立密钥管理和真实的 `SMS.Issue` / `Exchange.Subject` 适配器（服务端验证授权码、签发方、受众、有效期及防重放）；本卡不把设置环境名或填写占位凭据视为生产可用。T28/T29 仍须验证系统权限和会员权益，T34/T35 仍须完成备份恢复与各业务模块最终清单联验。

## 下一任务及注意事项

T06 等接新路由时只放行明确实现的操作，从 `principal(c)` 取当前会话；业务读写在 `Accounts.WithSession(ctx, p, false, fn)` 的同一事务内进行。采集方在该事务内调用 `accounts.Granted`，无授权或读取失败不采集。`listConsents` 返回当前决定而非审计历史；移动端换账号隔离缓存，倒计时从服务端 `frozen_until` 计算。T07 使用稳定的 `app_account_token`；每个新数据模块在 `service.Start` 加入必需清单并注册两个钩子，再开放业务路由。

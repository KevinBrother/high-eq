# T18 · 场景选择与关系人手记

## 范围和入口

- 四个首页都可点「切换练习场景」进入 `/scene`；「我的 → 关系人手记」进入 `/contacts`。实现与组件测试分别在 `app/lib/features/contacts/`、`app/test/contacts/`。真实模式未登录不读关系人；模拟模式标明「不会发送数据」。
- 新建时先提示保留期，填称呼和场景，再逐题回答 T25 下发的 5–8 道题。可以回上一题或选「还不确定」；按题 ID 提交，不用题序充当 ID。编辑仅改称呼、场景，不用 PATCH 重发问答。详情按条展示交流线索、把握度及「仅供参考」；仅伴侣可展示亲密相处线索。
- 聊天导入是详情页上的**可选**操作：先告知含他人信息、原文 24 小时内删除与画像保留期，再允许粘贴。提交后清输入框；不写草稿、离线队列或日志。危机响应只显示服务端安全提示；审核故障不当成危机、也不当成成功画像。
- 使用 `listContacts` 的全部分页（含 `profile`）与 `getEntitlements`，不按本机时间戳猜测最近使用者。免费限 1 位；详情只读不等于可用于训练或反馈。「改选」有独立确认，向 `chooseContact` 提交并重新读取整个列表；其他记录不删除。回到前台、到达会员到期时间、手动刷新均重取权限；无法确认权益时不开放选用/编辑/导入。**删除是隐私操作**，即使只读也可请求；先确认级联范围，收到 `deleteContact` 的 `ok:true` 才刷新，不在客户端伪造级联清理。
- 默认从 T16 的生成示例载入问题、画像与免费权益，内存模拟额外放一位只读关系人以便手测改选。模拟不做画像推断；删除示例至空列表可走完整新建向导。后续指向测试服务只改 T16 的 `APP_ENDPOINT`，不改 UI。

### 画像文案验收样本（与 T25 共用）

句首用「可能的倾向」，描述可观察的行为，不认定动机或疾病。禁用绝对化表达：一定、绝对、肯定、必然、总是、每次都、毫无例外、永远、从不、从来不、天生、注定、必定、百分之百、100%；禁用诊断/贬损标签：人格障碍、抑郁症、躁郁症、双相、精神病、焦虑症、自恋狂、控制狂、有病、诊断、确诊。摘要或单条标签命中时整条替换为「线索还不够，可以再观察几次」，不把原句加上“可能”继续显示。此显示层兜底**不替代**后端生成与审核。

| 服务端给出的线索 | 可展示的白话示例（接在「可能的倾向」后） |
| --- | --- |
| 开放性高 | 愿意试试不熟悉的办法 |
| 尽责性高 | 喜欢事先说好安排 |
| 外向性高 | 更愿意把想法说出来 |
| 宜人性高 | 会先听听别人的需要 |
| 竞争型 | 遇到分歧时更想说明自己的立场 |
| 合作型 | 愿意一起找兼顾双方的办法 |
| 妥协型 | 愿意各让一步 |
| 回避型（分歧） | 想先缓一缓，再谈分歧 |
| 回避型依恋（仅伴侣） | 在亲密相处时需要一些独处空间 |
| 焦虑型依恋（仅伴侣） | 在联系减少时想得到回应 |

### T18 × T05/T25：首用授权真实 UI 联验（2026-11-21）

原缺口：新增说明与导入复选框都没有写 T05 的用途授权。现在新增、修改与改选需要 `contacts`；导入同时需要 `contacts`、`chat_import`。进入时读取当前账号分页决定，缺哪项单独询问哪项。只有点击「同意并继续」才 PUT 对应的 `purpose`、`version: 2026-11` 和 `granted: true`；核对回执后再开放对应表单。「暂不同意」或返回不申请授权、不发送内容。聊天片段的分享权确认仍逐次要求，不等同于 T05 授权。查看与隐私删除不要求重新授权。

| 真实操作 | 观测结果 |
| --- | --- |
| 新账号拒绝新增，再主动同意 | 拒绝后授权 PUT 和新增 POST 均为 0；同意后从 T05 回读只有 `contacts`。 |

### 到期→最近使用→改选→续费正常旅程（2026-11-26，随仓验收）

两次独立复核均已关闭同一合成账号两位关系人的正常子项，只关闭该子项。两次分别以「到期前显式改选」和「会员期真实发送对练消息」建立最近使用者；后者补齐了 `ForModel` 实际使用入口。现已把后者的 real-use 版本随仓：具名 Go 用例 `TestT18SelectionRenewalJourney`（构建标签 `integration && t18selection`）驱动生产 `ContactsWorkspace` 页面，由 `app/tool/t18/verify_selection.sh` 在自建一次性 PG17/Redis 上实跑；独立复核归档只作历史记录，不再是当前唯一入口。

```sh
# 仓库根；initdb/postgres、redis-server、go、flutter 在 PATH，app 依赖已锁定
PATH="/usr/lib/postgresql/17/bin:<redis-bin>:$PATH" bash app/tool/t18/verify_selection.sh
```

- 入口复用已准入的 `app/tool/t27/history_journey.py` 隔离环境与自建存储，不另写进程管理，也不接受外部传入 `DATABASE_URL`/`REDIS_URL`；成功必须出现具名 `--- PASS: TestT18SelectionRenewalJourney`、`PASS(service.recent-use)`、`PASS(page.journey)`、`PASS(go.journey)` 和 `stage=complete fixture_expire_editable=1 fixture_renew_editable=2 selection_requests=1` 回执，skip 或缺回执不算通过。
- `T18_DISPOSABLE=yes` 由入口注入；源码与 Flutter 分别从正常 checkout 自身和 PATH 解析，不依赖交接目录或本机绝对路径。
- `.github/workflows/t25-contacts.yml` 新增 `t18-selection` job：先 `server/` 的 `go mod download`，再进入离线入口；push/PR 触发已包含该用例及直接产品/共用测试依赖。未改动其他工作流。

复做场景（真实接口 + 生产 `ContactsWorkspace`）：

1. 同一合成 Apple 账号登录后，先按正常产品流程同意 `contacts` 用途；未登记该同意时建档会被拒绝。
2. 准备覆盖当前时刻的会员权益：夹具插入合成 `paid` 订单和当前有效的 `entitlements` 区间。免费档只有 1 个名额，故需先有该区间再创建第二位。
3. 再经产品接口创建甲、乙两位关系人；初始两位 `editable=true`。
4. 建立最近使用者（两条独立前置分别复做）：对乙调用 `POST /v1/contacts/{id}/activate`；或先按正常产品流程同意 `practice`（建会话即校验），再为乙创建自定义对练会话并发送一条普通消息，收到 SSE `reply_saved`。
5. 夹具把同一个 `entitlements` 区间的 `ends_at` 推到过去，手动刷新页面。
6. 正常浏览甲详情并返回，打开「改选为可用关系人」再取消。
7. 再次打开改选，点「确认改选」甲。
8. 夹具另插一笔合成 `paid` 订单和覆盖当前时刻的会员区间，保留原区间的到期状态；然后卸载并重新挂载页面。

| 观测点 | 结果 |
| --- | --- |
| 会员期、建会话未发消息 | 甲、乙 `last_used_at` 均 NULL；建会话不写。 |
| 正常发送并收完 SSE | 乙非 NULL、甲仍 NULL；写入发生在 `claim` 事务内的 `ForModel`→`Choose`→`SelectContact`，早于模型生成和 `reply_saved`，不是建场或回执时才写。 |
| 夹具到期、手动刷新 | 真实权益与关系列表回读 `tier=free`、`max_active_contacts=1`，唯一可用为最近使用的乙；页面乙「可用」、甲「只读」。 |
| 浏览甲、打开改选再取消 | 两步均未发出 `activate`，回读仍只有乙可用。 |
| 确认改选甲 | 整段页面旅程只 1 次 `activate`，目标甲；甲可用、乙只读，页面显示「编辑资料」；旅程末尾 PG 回读两人均非 NULL，甲晚于乙。 |
| 夹具续费、重新挂载 | `tier=member`，列表两条均 `editable=true`，页面两位均「可用」。 |

边界：到期和续费都由夹具改合成 `entitlements` 区间模拟，未验真实购买、收据、商户链路、自然到期、前台恢复或定时刷新；续费只断言两位恢复可用，未单独断言会员档位的 `max_active_contacts` 字段值。对练回复由本地脚本化合成供应商生成，不是外部模型或生成质量验收。只读甲仅被正常浏览和通过产品允许的改选恢复可用；未验只读编辑、推断、训练、反馈的拒绝，也未扩展到跨账号、权限异常、聊天分支、到期清理、导出删除、真实交易或真机。随仓入口只复做第 4 步的对练消息路径（不调用显式 `activate` 建立最近使用者）；其余结论仍不声称本仓或 CI 已有独立测试。

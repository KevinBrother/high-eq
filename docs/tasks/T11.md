# T11 · 提示词模板与版本管理

## 范围和入口

T11 接入现有 Go 服务，不新增 App 接口、不预置业务提示词，也不实现 T15 页面。

- **保存草稿**：运营人员经 T13 鉴权调用 `POST /admin/v1/prompt-versions`，传 `task` 和 `template`。每次保存追加新 UUID 和任务内递增版本号，不改变线上指针；草稿也不能覆写或删除。`GET` 同路径支持按任务过滤、按版本从新到旧翻页。
- **上线、分流、回滚**：`PUT /admin/v1/prompt-releases` 一次提交 `task`、`model_id`、`primary_version_id`、`experiment_version_id`、`experiment_percent`；`GET` 同路径可分页查已发布配置。实验比例 0–100；非零须有不同的实验版本，两版本须同任务、模型不能是审核模型。回滚时将主版本指向历史 UUID，实验版本显式置 `null`、占比置 `0`。事务提交后，下一次选版直接读 PG 主库，不等 TTL 或广播；已选版的在途尝试不撤回。写操作复用 `adminops.commitWrite`，不把模板或变量传入审计。
- **模板语法**：UTF-8 文本，`{{scene}}` 与 `{{ scene }}` 等价；变量名区分大小写，匹配 `[A-Za-z_][A-Za-z0-9_]*`。双花括号用于占位，单花括号是普通文本（嵌套 JSON 的相邻结束括号可写作 `} }`）。不执行表达式、函数或递归替换。缺键报 `prompts.ErrVariable`，多余键忽略；显式空字符串与缺键不同，但渲染结果不能全空白。模板上限 64 KiB，结果上限 256 KiB，错误不回显内容。
- **任务变量契约**：`role_play` 只可用 `{{scene}}`；`scoring` 只可用 `{{assessment}}`、`{{target_item}}`、`{{retry}}`；`profile_inference` 只可用 `{{scene}}`、`{{options}}`；`reply_suggestion`、`review_analysis`、`content_generation`、`classification` 不得使用变量。变量名和任务必须同时匹配，跨任务变量按不支持变量拒绝。
- **保存与发布校验**：保存草稿和切换发布指针都在写库前执行同一套任务级校验。校验要求模板语法有效且不超过 64 KiB、用每个任务必然提供的合法输入渲染后非空，并按生产调用实际变量上限计算 256 KiB 展开边界：`role_play.scene` 94 字节；`scoring.assessment` 12 字节、`target_item` 11 字节、`retry` 96 字节；`profile_inference.scene` 7 字节、`options` 当前序列化 501 字节。`target_item` 和 `retry` 在部分合法评分调用中为空，因此不能只靠它们产生可见内容。后台对变量错误和模板语法/大小错误返回不同的固定 400 文案，不回显模板或变量内容；管理页优先显示结构化 `Error.message`，仅在响应不是可解析 JSON 时回退到固定状态文案。
- **存量模板与回滚**：发布或回滚前先盘点该任务的全部版本及其关联模型，确认当前指针、实验版本和候选历史版本均满足上述契约；发布事务在移动线上指针前重新校验主、实验版本。历史 UUID 不能绕过任务级校验，非法版本会被拒绝且原指针保持不变。
- **场景数据边界**：目录关卡使用服务端冻结的场景文本作为 `{{scene}}`。自定义情境的完整文本只进入首条 `user` JSON 的 `scenario`；系统变量只能收到经白名单校验的场景类别（如 `work`），不能把用户自填文本提升为系统指令。空值、非 UTF-8、NUL、全空白或超过 6,000 字节的自定义情境在创建会话时拒绝。
- **业务入口**：从 `runtime.StartGateway(ctx)` 得到 catalog，以 `catalog.NewRouter(runtime.Data, stop)` 注入业务。任务、变量和可选的 `user` / `assistant` 对话是调用输入；账号来自认证上下文，模型和版本都不是业务参数。`system` 消息由网关生成。保留 T10 对 `Terminal` 和错误的处理，不能据此保存评分或成功扣次。

```go
reply, err := router.Run(ctx, gateway.Call{
    Scope: gateway.Scope{User: authenticatedUser, Operation: requestID},
    Task: gateway.RolePlay, Mode: gateway.Text,
    Variables: map[string]string{"scene": scene},
})
```

T10 先按账号选主/灰度模型；对**实际尝试的模型**，`internal/prompts.Resolve` 使用独立命名空间 `prompt-ab:v1`、任务、模型 UUID 和用户 UUID 计算 SHA-256 桶（前 8 字节大端整数模 100），桶号小于实验占比才进入实验。发布或回滚不重新随机分桶，不存用户分组表。每次选版在一条 SQL 内读取发布指针和所选模板；缺发布或变量时，此尝试既不发往审核也不发往生成服务。切备用重新选版、渲染、审核。生成成功/失败的每次尝试均通过 `ai_calls.prompt_version_id` 关联实际版本；独立审核调用不冒用生成版本。渲染文本和变量只在请求内存中使用，不入库、不写日志。

实现：`server/internal/prompts/`、`server/internal/gateway/{prompt,router,store}.go`、`server/internal/adminops/{prompts,prompt_lists}.go`。迁移 `20261121210011_prompt_releases` 增加发布指针、复合外键和版本不可变触发器；数据归属见 `docs/schema.md`。

## 验证命令及实际结果

- `./server/tests/migrations.sh`：PG17 空库迁移、约束断言、回滚到空库、重新应用均通过。
- 使用独立 PG17、Redis 8.2 及独立的删除登记 Redis，应用本卡迁移后执行 `cd server && go test -race -count=1 -p=1 -v -tags integration ./internal/prompts ./internal/adminops ./internal/gateway`，三包全部通过。`TestConcurrentDraftNumbers` 检查并发版本编号；`TestPromptLifecycle` 通过管理 HTTP 和数据库验证发布、回滚、审计及拒绝非法配置。`./server/tests/runtime.sh` 的容器化作业也覆盖这些用例。
- 模板/网关测试覆盖未定义变量时无外发、严格单次替换、10 万个合成账号按实际模型稳定分组、备用重新选版审核、实际使用版本关联与不复制正文。单卡交付及合并后的工作流以相应提交的 `T04 server`、`Verify` 和 `Migration history` 结果核验。
- 本轮任务级边界回归实际执行 `go test ./internal/prompts ./internal/training ./internal/scoring ./internal/adminops ./internal/service`、`go test ./internal/profile` 和对应 `go vet`，全部通过；`go test -tags integration -run '^$' ./...` 与 `go test -race -tags integration -run '^$' ./internal/service` 仅完成编译，未运行真实 PG/Redis 用例。新增非法 UTF-8 回归先复现标准库把模板字节静默替换为 `�` 后接受，修复后在 JSON 解码前校验原始请求体，handler 级测试确认固定 `400 invalid_argument` 且不回显内容。oapi-codegen v2.5.1 重生成、双 OpenAPI YAML 解析和后台任务提示静态分析通过。

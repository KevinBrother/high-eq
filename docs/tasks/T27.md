### 主要交互

- **今日计划**：展示已完成数与服务端计划项。小练习和知识卡在底部面板中完成；对练项跳到 `/training`。完成计划项后使用完成响应更新连续天数，并避免较早发起的刷新覆盖新状态。
- **读人小练习**：加载题目和选项，选择后请求判定，显示“读到了 / 再换一个角度”和解析，再完成今日练习。提交失败保留重试，不显示异常对象或响应正文。
- **知识卡**：从计划项打开卡片正文，支持选择文本；阅读后可记为完成。计划外知识卡也可从首页列表阅读，不强制打卡。
- **真实标记**：使用 T32A 的 `MarkBook` 和 `MarksPage`，读取 `manual_mark` 同意状态；创建使用可复用请求 ID，一分钟内重复点击由服务端合并；历史支持游标分页；删除已提交但响应丢失时，后续 404 视为已达到目标状态。
- **成长档案**：复用 T17 雷达图，只传 `SEA`、`OEA`、`UOE`、`ROE` 四个 WLEIS 维度和最近两次原始 0–100 百分值；训练参考分独立展示，不混入雷达轴。
- **历次得分**：整场对练显示 `NVC / 100`，单项练习显示目标项 `/ 25`；单项只说明目标项过关进度，不进入训练参考分。`listSessions` 仍按创建时间分页，客户端会遍历全部游标，再按 `completed_at` 降序排列；未知时间排最后，同完成时间按 `session_id` 降序稳定排列。历史缺值显示“完成时间未记录”，不冒充“最近一次”。
- **复测提醒**：按最近一次测评的 `next_eligible_at` 显示未到期或已到期状态，截止时间到达和应用前台恢复时都会刷新提醒。当前只是 App 内提醒，不申请系统通知权限。
- **成就**：连续 3 / 7 / 30 天阶段成就；完成计划项后只弹新增阶段，已有成就与缓存中的历史成就合并，不用一次响应覆盖历史。
- **状态处理**：在线失败时读取账号级加密缓存并显示离线横幅和重试；401/403 清空页面快照并删除账号缓存，不读取旧缓存。业务请求已收到 401 后，若 refresh 返回 5xx/超时或重放仍为 401，客户端也清空当前账号作用域并抛标准 401；请求前 access 已过期但 refresh 暂时失败、以及普通业务 5xx，则保留账号和可恢复离线状态。跨账号切换会重建仓库并丢弃旧账号迟到响应。并行读取失败按 `SessionChanged`、401/403、普通失败排序，授权拒绝不会被普通 5xx 掩盖。

### WLEIS 与训练参考分的边界

- 雷达只接收 `AssessmentData.dimensions` 中的四个 WLEIS key，图上固定四条轴；训练参考分、整场对练得分、单项进度和情绪数据都不会传给 `AssessmentRadar`。
- `AssessmentRadar` 复用 T17 的原始百分值和分档逻辑，新增可选的 `beforePercentages`，但仍只画四维；同时保留数值、分档和读屏文本替代。
- `training_reference == null` 时不显示分数，也不从 `wleis_percent`、单项得分或本地数据推算分数，显示精确文案：
  `完成一次整场对练或完整复盘后解锁训练参考分`。
- 单项练习只显示目标项进度（满分 25）和“不计入训练参考分”；不生成训练参考分，也不改变有效行为次数。
- 服务端返回 `valid_behavior_count == 0` 且 `training_reference != null` 时，模型层直接拒绝该快照，避免把不合法响应渲染成可比较分数。

### 缓存与账号隔离

- 在线读取成功后，将 `GrowthSnapshot` 写入 T16 的账号级 `Sessions.put`，使用 `CacheKind.continuation` 和固定 ID `growth.snapshot.v1`；缓存本身由 T16 的账号作用域与 AES-GCM 机制保护。
- 得分缓存包含可空的 `completed_at`。旧加密缓存缺少该字段或显式 `null` 时按未知时间读取；仅无法解析的非空值会被拒绝，日期逻辑越界可能被 `DateTime.parse` 归一化（`2026-02-30T00:00:00Z` → `2026-03-02T00:00:00.000Z`），不能写成所有非法值都会被拒绝。在线刷新成功后以服务端当前历史覆盖缓存，已删除评分不会从成功刷新后的缓存回填；若删除后首次在线刷新得到 `503`，页面会按读取失败展示账号级缓存，因此在随后成功刷新前仍可能看到删除前记录。
- 读取失败才尝试 `cached()` 并标记离线；缓存损坏或不可用不会遮住重试入口，也不会让在线成功被误报为离线。
- `growthRepositoryProvider` 监听 `Sessions.identity`；身份变化时重建仓库。页面用仓库实例和加载代次双重校验，旧账号的迟到响应不能覆盖新账号。
- 账号切换或 `SessionChanged` 时清空页面快照并显示“账号已切换，请重新打开页面”，不保留上一个账号的计划、成就或分数。
- 完成写入会推进缓存代次；打卡成功后，即使较早发起的刷新晚到，也不能把完成状态回滚。

### 合成 Demo 边界

默认 `ExampleTransport` 下使用 `DemoGrowthRepository`：只返回符合 App 契约形状的合成计划、四维、训练参考分、对练记录、知识卡和小练习，并在当前账号生命周期内保留完成状态。它不写入 `Sessions`、不持久化、不发网络请求；切换到真实 `APP_ENDPOINT` 后使用 `ApiGrowthRepository`。

演示计划中的对练项使用稳定常量 `demoPlanLevelId`，练习路由和成长计划通过 `demoPracticeProvider` 共享同一个 `DemoPractice`。从首页计划进入该关卡并完成评分后，返回首页重新读取计划会把对应项标记为已完成，不再出现“已删除或不可用”或两个仓库状态不一致。Demo 中的分数与内容仅用于交互开发，不是 T26 数据，也不是行为评分证据。

## 可访问性与适配

- 练习首页使用一次性构建的 `SingleChildScrollView + Column`，确保暂停自评返回后，即使续答入口位于首屏下方也已挂载并可发现；成长档案使用 `ListView`。窄屏和大字号时通过 `useStackedLayout` 将标题与操作、分值和说明改为纵向排列。
- 320px 宽、1.8 倍字号下练习首页和成长档案均有自动化用例覆盖可滚动与无溢出。
- 标题使用语义 header；加载、错误和解析结果使用 live region；雷达每维提供“最近一次/更早一次 + 分数 + 分档”的语义标签，图形本身从语义树排除。
- 成就条每个阶段使用独立 `Semantics(container: true)` 节点，读屏可逐项浏览；颜色不是唯一信息，分数和状态同时以文字表达。
- 对练、续答、手动标记、场景四个快捷入口在外层语义节点直接暴露 `tap`，视觉 `InkWell` 保持原有触屏行为，读屏可独立激活每个入口。
- 计划项、知识卡、得分进度和离线状态均有文本状态，不只依赖图标或色彩。
- 真实标记页保留同意对话框、明确拒绝路径、错误 live region、刷新/重试和删除确认；快捷标记不会绕过同意。

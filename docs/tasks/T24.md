## 已审功能

### 表单与草稿

- 四步收齐发生经过、我的感受、对方可能的感受、我的行动、下一次行动五段文字。
- 输入即保存草稿；切步、打开页面、保存草稿和授权确认失败都不会调用复盘提交，不会计次。
- 草稿使用既有 T16 账号级 AES-GCM 存储边界；读取、保存和条件删除按账号串行，跨页面实例也不会让旧删除覆盖新保存。
- 成功提交后先等待所有在途保存结束，再条件删除匹配当前请求 ID 和规范化内容的草稿，避免旧请求晚到后误删新稿。

### 请求键与响应丢失

- 每次提交前先把完整请求快照写入既有加密草稿缓存；快照不进入 wire 请求。
- `possible_attempts` 平铺保存可能已经发出的请求正文与原 `request_id`。响应丢失、重开、编辑再撤销后，规范化正文和关联字段一致时继续使用原请求键。
- 内容实质变化后再次提交才生成新键；安全分流后选择“重新写一次”会主动换新键。
- 202 处理中、503 可重试和 HTTP 500 均保留原请求快照并使用原 ID 重试；500 不承诺未计次，固定提示“可能已生成并计次”。

### 授权与隐私

- 首次提交和每次重试原请求都会重新查询复盘授权；未授权时展示明确确认，说明五段文字可能包含他人信息、服务器加密保存期限以及只填写有权使用的信息。
- 授权等待前捕获编辑 revision，授权返回后若内容已变化，不提交旧快照。
- 请求快照落盘后、正文发送前再次核验授权；撤权或查询失败时不发送正文。
- 请求只包含复盘契约字段，不包含音频、录音或本地草稿快照。
- 授权、session 和账号作用域继续走当前 `AppApi`/`AccountScope` 边界；切换账号后旧页面读取会由现有 session 校验阻断。

### 踩坑本

- 成功后递增页面内 revision，并在每次从“写复盘”切回“踩坑本”时重新查询，能接收跨页面成功提交的新记录。
- 列表请求带 generation 防旧响应覆盖新结果；场景、关系人和游标分页继续使用契约字段。

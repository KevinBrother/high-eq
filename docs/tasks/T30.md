# T30 · 情绪识别服务

## 范围和入口

- 已接 T03 的六个 operation：`uploadWindow`、`deleteWindow`、`getBaselines`、`reportSignalEvent`、`listSignalEvents`、`annotateSignalEvent`。入口为 `server/internal/service/emotion_http.go`，业务在 `server/internal/emotion/`。不改生成契约，不涉及免费手动标记、设备、推送或模型。
- 上传只接受单渠道、UTC 对齐的 30 秒聚合；拒绝音频、转写、逐秒数组、越界时长。同键同值幂等、异值 409。T05 会话锁内检查当前授权且采集时间不早于本次同意；T06 复用已付费的连续权益区间，过期或重新订阅不补传断档前窗口。导出/删除不要求会员或继续同意。窗口、事件使用与账号、记录绑定的 AES-GCM 信封。
- `baseline.go` 按账号时区、各特征有效秒数分别计算；1800 秒/日、7 个有效日才返回按时长加权的基线和绝对上界。静音不补秒。两分钟步频取最近四个对齐槽中有覆盖的步频均值（按有效秒加权）；运动槽不累计。HRV 单列读数和采样日，不计时长。统计、阈值和误报调整从 180 天内现存源按需生成，不另落长期画像。删除窗口即会影响下次计算。
- `reference.go: Decide` 比较同窗均值与就绪上界（含相等）；音量/音调合为一类，任一提醒冷却 600 秒。只有已放行的实时 Watch 心率加语音异常是**本人候选**；两类混合语音异常、本人心率正常或缺失只得**对话节奏**。服务端按本账号实际窗口重新判定，不信任客户端传入的分类；历史判定不把目标槽算进自己的参考基线。生产放行仍由 T06 `WatchAlert` 控制，未开启。
- 节奏可补场景，不可核对为本人；候选初始亦不产生画像反馈。首次明确 `yes/no` 才在同一事务保存核对、时间和随机反馈 ID。重复同答不再调阈；相反回答返回 409。`no` 仅对该候选实际命中的上界累乘 1.05，至多初始 1.5 倍；音量是可为负的对数 dB，调初始 **+6 dB 偏移**到最多 +9 dB，不把负数乘大而降低门槛。待投标记随源删除，维护任务在提交后交给 T25；重投保留原 ID/时间。T25 按 ID 去重，在事件事务中用 `Emotion.Confirmed` 读取肯定/否定，不携带原始特征。
- `20261121233030_emotion_roots` 增加内部不可复用 `purge_id`，保留外部 `(账号,渠道,起点)` 幂等键。在 T04 账号锁内解析后交协调器登记，登记里没有账号、渠道或时间线。窗口/事件在 180×24h 边界即不再读取、导出或参与阈值；分钟维护循环走协调器物理清理。`emotion.json` 流式导出本账号存活聚合、事件和基线，不含清理键、密钥或投递状态。

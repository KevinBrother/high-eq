# T29 · 本地语音特征提取（客户端）

## 范围和入口

- 本卡只交付语音特征、录音保留和本机回听；不做情绪判定、云端转写、逐秒/原始音频上传或服务端接口改造。情绪规则和同窗提醒归 T32B。
- 入口为 `app/lib/features/voice/`：
  - `features.dart`：16 kHz 单声道 PCM16LE 分析、严格统计 wire 对象和转写不可用状态。声学音节速率代理只保留在本地分析/旧队列读取中；上传边界不发送 `speech_rate` 或 `speech_rate_unit`。
  - `aggregator.dart`：基于原生样本采集时间对齐的完整 30 秒窗口；前导碎片、不足 30 秒的尾部和采样缺口均丢弃，不用回调到达时间拼接窗口。
  - `access.dart`、`cleanup.dart`、`controller.dart`、`retention_janitor.dart`、`store.dart`：独立授权、会员门禁、本机加密队列、录音索引、逐项清理证据和撤回状态。
  - `page.dart`：可见录音状态、计时、录音/不录音文案、统计摘要、回听和撤回操作。
  - `platform.dart`：唯一的原生 PCM 边界；事件格式为 `{pcm, captured_at_us}`，Android `VoiceCapture.kt` 和 iOS `VoiceCapture.swift` 只处理内存 PCM，不写文件、不转写、不联网。样本时间取自录音硬件/音频时钟：Android 使用 `AudioRecord.getTimestamp(..., TIMEBASE_BOOTTIME)` 和帧位置映射块起点，API 24 以下 fail-closed；iOS 使用 tap 的 `AVAudioTime.hostTime` 映射启动锚点。时间戳缺失、过期、倒退或非有限时停止采集并上报 `capture_timestamp_invalid`，不以回调墙钟补洞。
- 共享接线包括 `main.dart` 的 `/voice` 路由与应用级 janitor host、`features/home/shell.dart` 的“我的”入口、Android 权限/Activity、iOS AppDelegate/Info.plist/Xcode 文件引用，以及 `core/api.dart` 的可选 guarded send/401 replay hook；该 hook 只供需要发送前复验隐私条件的调用使用，测试替身已适配新增可选参数。
- 采集链路：
  - 16 kHz、单声道、PCM16LE、50 ms 帧。每帧计算 RMS dBFS；能量达到 `-48 dBFS` 才计入人声。音调用 80–400 Hz 自相关估计；本实现原有的语速字段是能量峰得到的**声学音节速率代理**，不是逐字转写语速。该旧值可继续从旧加密队列读取并用于本地摘要显示，但网络发送时省略，不能作为 `characters_per_second` 新窗口上传。
  - 每帧/每秒中间值只存在于本机分析调用和内存中，不持久化、不进队列、不进入 wire 对象。当前手机上传的 30 秒窗口只含 `voiced_seconds`、音量和音调统计；旧队列中的无单位声学代理会在 `VoiceWindow.toWire()` 边界剥离。各特征的 `valid_seconds` 不超过 `voiced_seconds`。
  - 纯静音返回 `voiced_seconds: 0` 且三个特征为 `null`，不累计人声秒数。
  - 本卡没有离线识别模型：`transcriptionStatus == unavailable`、`transcript == null`、`requiresCloudTranscription == false`；页面明确显示“转写不可用”，不会自动改用云端识别。
- 授权与可见性：
  - `voice` 是会员语音特征的独立同意；系统麦克风权限只在用户同意并点击开始后检查/请求。`audio_retention` 是另一个独立同意，默认关闭；拒绝或关闭它不影响已授权的统计特征分析。
  - 录音保留只接受完整 30 秒窗口；关闭时请求删除本机已有录音。清理器逐项记录结果，只有 `recordingsCleared` 等结果确认成功才显示“已删除”；删除失败时回听保持关闭并提示重试。录音元数据和 PCM 使用 T16 `Sessions` 的账号作用域 AES-GCM 存储，不存明文路径；回听前重新检查会员、`voice` 和 `audio_retention`。
  - 录音按 `starts_at + 3 天` 到期，恰好 3 天即不可读。应用级 `VoiceRetentionJanitor` 监听账号 identity，在启动、账号变化、每分钟 sweep 和 app resume 时清理当前 scope 的过期录音；语音页控制器 timer 只负责页面即时刷新，离开语音页后 janitor 仍继续工作。每次清理捕获当前 scope，不串账号。A 退出后 B 登录，旧 scope 的队列、录音和回听状态均不可访问，内存展示也清空。
  - 撤回顺序为：写入 fail-closed 标记、停止采集和回听、清空待发窗口与录音、再尽力同步服务端。清理器分别记录 marker、原生停止、回听停止、队列删除、录音删除和服务端同步结果；只有对应效果确认成功才显示“已停止/已删除”，同步失败或断网时标记保留，后续恢复联网也不会补传撤回前的窗口。
  - 采集期间页面始终显示“正在本地分析语音（不保存录音）”或“正在录音并本地分析”及计时；应用进入后台立即停止采集，启动中的采集也会被取消。

## T29/T30 语速单位交接（本归档）

本轮只迁移下游语义、手机发送边界和 wire 契约，不补 T29 的原生转写能力，也不修改 Swift/Kotlin。当前 `features.dart` 仍产生声学代理且 `transcriptionStatus == unavailable`，因此新录制和既有加密队列在上传时都省略 `speech_rate`；本地摘要仍可显示该代理，不能给它补一个单位后上传。冻结归档中不存在 `transcript_rate.dart` 或对应测试，后续设备端转写消费实现不得把本文规则冒充为已有运行时能力。

Flutter 消费方必须按以下规则生成一个新单位窗口：

- 只接受 `finalized` 且 `onDeviceOffline` 的转写；`partial`、`unavailable`、`cloud`、`other` 一律忽略。账号、语音会话和授权代次必须与当前采集一致，切换账号、结束会话或撤回授权后旧结果 fail-closed。
- 字符数为 Unicode grapheme 数：每个含 Unicode Letter 或 Number 的 grapheme 计 1。汉字、假名、拉丁字母和数字逐一计数，拉丁按字母而非单词，组合序列如 `Á` 计 1；空白、标点、纯符号和纯 emoji 计 0。含数字的 keycap 组合按“含 Number”规则计 1。
- 同一稳定 `audioId` 只取最高 `revision` 的 final 结果；重复投递、旧 final 和 partial 都不再计数。正文只在内存中计数，不持久化、不写日志、不进入队列或 wire。
- 分母是贡献了字符的转写 segment 有效区间长度并集，不是完整 30 秒、`voiced_seconds` 或所有 segment 时长之和。重叠区间只算一次；最终 `speech_rate` 的 `mean`/`maximum` 与计算结果同为字符/秒，`valid_seconds` 与这里的分母一致；只有一个窗口值时通常 `mean == maximum`。
- 一个 revision 的所有 segment 必须完整落在一个已知 30 秒窗口内。任何 segment 跨边界、revision 同时落入多个窗口、segment 零/负时长或同 revision 内重叠时，整条 revision 丢弃；不拆分、不四舍五入迁移、不重复归属。
- `recognizedCharacters == 0` 或有效分母为 0 时不得上传伪造的 0 语速，应省略 `speech_rate` 和 `speech_rate_unit`。上传窗口携带 `speech_rate` 时必须同时携带 `speech_rate_unit: characters_per_second`；不得单独上传单位。
- wire 只含 30 秒聚合字段，不含正文、PCM、音频字节、逐秒数组、账号 ID、会话 ID 或授权代次。服务端拒绝旧声学峰/分钟值的隐式换算。

上述字符计数和区间规则是未来设备端转写接入的验收契约，不是当前归档中的实现。真实正向计数还需要设备端 final revision、segment 区间、账号/会话/授权代次与 30 秒窗口对齐后另行联调，不能用声学代理或合成 PCM 冒充。

### 发布与回滚边界

1. **手机发送修复先于严格服务端写入生效。** 旧手机仍会发送无单位声学代理，候选服务会把整窗 400 拒绝；因此先发布省略代理、保留音量/音调的客户端版本，确认新录制和旧加密队列均按该边界发送，再让严格的新写入口接管。
2. **单位写入分两段启用。** 第一段只部署带单位密文的读取支持并保持写关闭；确认所有在服实例都能读取带单位窗口。第二段才允许未来转写链路发送成对字段。启用前还必须确认可回滚实例同样具备读取支持；若回滚目标仍是只会读旧格式的基线版本，一条留存期内的带单位窗口就可能使其基线/导出读取失败，禁止启用写入或执行该回滚。
3. **不得假定过去服务已会读。** 当前基线不能读取未知的 `speech_rate_unit`，本归档不补造线上开关、部署证明或历史服务兼容性；真实转写可用且读支持完成全量验证后，才讨论写启用。

## 复审修正与归档边界

本轮按 `build/t29/correction-vz0h1g4t/review.md` 和 `build/t29/correction-vz0h1g4t/parent-handoff.md` 的两个未解决阻断做窄修复，源码及文档读写限定在本归档 `src/` 内；未修改共享 checkout、未启动子会话、未提交、未推送。未生成或应用旧候选补丁，也不把本归档的局部验证写成整包或线上批准。

- **短句契约**：`valid_seconds` 收敛到 `voiced_seconds`，服务端 400/422 的确定性拒绝会丢弃坏窗口并继续后续窗口，避免队首毒化。回归：`sparse short utterance keeps feature seconds within voiced seconds`、`a rejected malformed window does not block later windows`。
- **启动取消**：最终门禁、原生启动和页面销毁/后台切换之间使用启动代际与取消检查；迟到的 `start()` 会补发 `stop()`，不会在页面退出后打开麦克风。回归：`cancelling the final gate never starts native capture`、`disposing during native start stops the late recorder`、`lifecycle pause cancels a start still awaiting consent`。
- **共享门禁**：`/voice` 只消费 T16 `consentProvider`，`VoicePage.forAccount` 强制注入同一个 `ConsentGate`；加载中不提前构造语音页，失败时显示 fail-closed 重试提示。回归：`voice route waits on the shared consent provider and fails closed`。
- **服务端 403**：立即停止原生采集、停止回听、清空待发窗口并保持撤回门禁。回归：`403 upload rejection stops native capture and playback immediately`。
- **撤回与清理**：`VoiceCleanupCoordinator` 分别记录 fail-closed marker、原生停止、回听停止、队列删除、录音删除和服务端同步结果；删除失败、原生停止失败或 marker 写失败均保留门禁并显示实际失败，不虚报“已删除/已停止”。重试撤回先重做本地删除再清标记。回归：`revoke keeps the persisted gate when local queue cleanup fails`、`retention deletion failure never claims recordings were deleted`、`native stop failure is reported without claiming capture stopped`、`playback stop failure is not reported as confirmed`、`voice revocation reports failed recording deletion without false completion`、`voice marker write failure keeps the in-memory gate closed`、`retention marker write failure keeps playback disabled`、`retrying retention revocation deletes locally before clearing the gate`。
- **发送前双重授权与账号复验**：首次上传在 `beforeSend` 异步检查之后重新 `sessions.require(scope)` 并读取当前令牌；401 刷新后重放前再次执行 `beforeSend`，账号被清、撤回或会员/授权失效时不会发出旧窗口。回归：`voice upload never sends after the account is cleared during beforeSend`、`voice upload rechecks revocation after a 401 refresh before resending`、`revocation before upload never marks or sends the queued window`。
- **采样时间**：原生事件携带 UTC `captured_at_us`，聚合器按样本时间而不是 Dart 回调时间切片；最后回调延迟仍可保留窗口，采样缺口/重叠丢弃 partial。Android/iOS 现在都不在采集回调中用墙钟计算样本时间；时间戳异常会停止采集。回归：`parses PCM together with its UTC sample capture time`、`rejects a PCM event without a native capture timestamp`、`rejects the retired bare-PCM event shape`、`sample timestamps preserve a window when the last callback is delayed`、`a sampling gap discards the partial window instead of splicing it`。
- **Android BOOTTIME 跨窗时间契约**：`captured_at_us` 表示硬件块首样本的 UTC 时间；相邻硬件块端点和首个整窗起点都只允许 1 ms 的硬件时间戳微抖。窗口完成对齐后，整窗完整性只由累计样本数（30 秒 × `sampleRate`）判断，不再拿首块时间与 UTC 窗边界比较。因此从边界前开始、仅边界块推迟 900 µs 的首个整窗不能丢，连续流的后续边界相位/累计漂移也必须保留整窗。5 ms 中断或重叠仍丢弃受影响 partial；恢复窗必须等真实样本补齐，不能按时标或补零凭空产出。回归：`continuous BOOTTIME jitter across a boundary keeps full windows`、`continuous BOOTTIME drift beyond 1 ms across a window keeps full windows`、`a 900 us boundary timestamp jitter keeps the first full UTC window`、`a 5 ms sampling interruption drops the affected window and recovers`、`a 5 ms sampling overlap needs five real ms to finish the recovered window`。
- **本轮验证边界**：已验 `dart` 运行的纯 Dart BOOTTIME 探针及严格契约（边界前首窗 `+900 µs` 得到 `[0]`、跨窗微抖/累计漂移得到 `[0,30,60]`、5 ms 中断得到 `[30,60]`、首段非对齐得到 `[30,60,90]`）；5 ms 重叠在 89.995 s 时只产出 `[30,60)`，缓存 `479,920` 个真实样本且无 `[60,90)`，补 5 ms 非零尾部后才得到 `[30,60]`。`dart format --set-exit-if-changed` 与聚合器/测试的 `dart analyze` 已执行。未验 Flutter 标准全套、远端 CI 和真机；全套由宿主执行，不用纯 Dart 探针替代。
- **Android 时间戳状态码**：`AudioRecord.getTimestamp(AudioTimestamp, AudioTimestamp.TIMEBASE_BOOTTIME)` 明确按 Android 的 `int` 返回码处理，仅 `AudioRecord.SUCCESS` 才继续；失败直接返回 `null`，由采集层 fail-closed，不回退墙钟。该问题属于编译级阻断，当前环境没有 Android SDK，须由主会话用不启用麦克风的 compile 检查验证。
- **并发录音索引**：`Sessions.runExclusive(scope, 'voice.recordings', ...)` 的队列位于共享 `Sessions` 实例，按账号 scope 和逻辑 key 隔离；页面、历史页、janitor、撤回清理即使各自构造 `VoiceWindowStore`，也会串行完成索引读取、PCM/索引写入和删除。`saveRecording`、`recordings`（含到期清理）、`readRecording`、`deleteRecording`、`deleteAllRecordings`、`purgeExpired` 均使用同一临界区，内部实现避免再次取锁。回归：`expiry cleanup and save serialize across independent store instances`、`single-recording delete and save serialize across store instances`、`clear-all and save serialize across store instances`；三条用例同时核对索引、可回听的新 PCM 和加密存储目录中仅剩 1 个新录音 `.audio` 文件，避免孤儿密文漏检。
- **三天到期**：控制器 timer 覆盖初始化、保存、刷新、删除及历史页跨边界；应用级 janitor 覆盖离开语音页但 app 仍运行、账号变化和 app resume。回归：`recording expires while the history stays open without user action`、`startup purges a recording exactly at its three-day boundary`、`purges expired recordings after the voice controller is disposed`。

已保留的安全/数据边界：PCM 只在内存和本机加密存储中流转，不进入 wire 对象；转写保持不可用；录音保留独立授权；账号 scope 隔离和回听前门禁不变。

## iOS PCM 采集修复

- 使用 `AVAudioConverter` 将麦克风数据转换为 16 kHz 单声道 PCM16LE。原生仍按 50 ms 输出，在首个完整 UTC 窗开始前按累计输入样本数截断前导残帧，从边界重新切块。恰好采齐的窗口在停采前就能送达，缺样的尾块不会输出。
- 按相邻 tap 的硬件时间和采样数判断连续性，容许 1 ms 微抖。检测到断点时丢弃残帧和转换器历史，仅在本次采集恢复后的首个完整 PCM 块携带 `starts_new_segment: true`。Dart 清空旧半窗，随即用同一块的采样时间和完整 PCM 切窗。若真实缺样未在相邻 tap 中产生超过 1 ms 的可见偏差，现有检测仍可能将其视为连续。
- 停止采集或取消 PCM 监听时，旧录音已排队的 PCM 和时间戳错误一并失效。
- 宿主合成测试覆盖真实转换器的 44.1/48 kHz 跨 30 秒窗口、时间微抖、5 秒中断和录音切换，Runner 已通过 iPhone Simulator SDK 编译。合成测试接入现有 macOS CI，远端 CI、iOS 整包和真机麦克风/中断恢复仍待验证。
- **边界回归**：48 kHz 两段合成输入经 `AVAudioConverter`、采集会话、生产 PCM 消息编码和 Dart 解析后切窗。修复前，即使恢复段恰好采满，UTC 碰撞时也只交付 `[0s, 30s)`，有可见时间间隔的对照能交付恢复窗。修复后碰撞场景两窗均交付，恢复窗 480,000 个样本与独立对照逐字节一致。两个时间戳相接的段仍会丢掉跨断点半窗，恢复段少一个输入样本时仍丢掉未满窗。

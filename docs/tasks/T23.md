# T23 · 文字复盘与踩坑本

## 范围和入口

- `POST /v1/reviews` 使用 T03 的五段 `ReviewInput` 和登录身份；先取得 T05 `review` 单独授权。有关系人时另查 `contacts` 授权及 T06 可写名额；标记、事件必须属于本人且未过 180 天。没有授权不调模型。仅关联来源，不上传传感器数据、音频、身份或来源 ID。
- 客户端为同一次提交保留 `request_id` 和原内容。进行中返回 `202 in_progress`；已完成返回同一 `Review`；同键不同内容 `409`。审核不可用是 `503 moderation_unavailable, retryable:true`，用原 ID 重试。明确危机（含评分返回 `safety_flag:true`）只有活动终态持久化成功后才回 `200 {safety:true,message:…}`，同键重试仍是求助对象；终态写入失败返回可重试服务端错误，不返回虚假的安全成功。生成/格式失败没有评分或净扣次，不用新 ID 自动循环。
- T10/T11 两次非流式业务调用：`review_analysis` 只生成可单独校验的一句修复话；`scoring` 走 **T12 `Score`**，只有 `my_action` 是第 1 次、也是唯一一次用户行动。背景、双方感受、下次计划、可选画像只供理解，不是待评分发言。四个 NVC 分项的问题理由、三个情绪等级、改写、解释保留在源评分。无硬编码模型/系统提示兜底。
- `GET /v1/reviews` 是本人已完成的踩坑本，支持 `scene`、`contact_id`、`limit`（1–100）、`cursor`，按服务端创建时间及 ID 倒序；`GET /v1/reviews/{id}` 取相同详情。失去新训练权限不等于丢掉自己的历史。`DELETE /v1/reviews/{id}` 在账号内将公开活动 ID 转为不可复用的源 ID，走 T04 数据删除登记，不是退款操作。

**结算边界。** `(user_id, request_id)` 唯一；幂等指纹是绑定账号和用途的 HMAC。首次占位提交时就有服务端 `activities.id/source_id`。持 T06 工作令牌者在事务外调用 T10，断网不当主动退出。修复话通过审核后可加密作检查点；修复话或评分的完整模型输出在输出审核前也先写入 **15 分钟短时加密检查点**。输出审核不可用时保留检查点，原键重试只重做输入/输出审核和解析，不重复调用已返回完整输出的模型。检查点绑定账号、复盘活动和任务，不进入历史、ZIP、API 或错误信息；成功、失败、危机及活动级联删除会清除，只有审核不可用且未过期才保留；分钟维护会主动物理清除超过 15 分钟的检查点，即使无人用原键重试。检查点一旦过期，原请求键永久失败关闭并返回 `409 conflict`，不得丢弃后静默重算；客户端必须使用新的请求编号重新提交。过期清扫先锁用户和 `review_requests` 行，再原子清密文、置 `generated_expired`、失败 held 工作令牌及活动；成功结算在同一事务内锁读该标记，清扫先到时旧 worker 的日记、评分、关联和扣次全部回滚，结算先到时清扫跳过已清除检查点。输入审核 allow 后、模型生成前会在账号锁内再次重查授权、名额和关联来源；主模型失败进入备用模型时，在备用轮的输入审核发送前再预检一次，撤权后不会新增审核或生成外发。工作令牌同时栅栏检查点和终态，旧 worker 不能覆盖新 worker 的活动状态；过期后的迟到 `failed` 收尾也不能清除永久过期标记。保存检查点和最终成功事务前都重查会话、授权、名额和关联来源。`SaveApproved` 的同一 SQL 事务写日记、T12 源明细、成功评分调用关联、待发位及扣次；任何一项失败全部回滚。相同请求的成功重放不再分析、评分、发事件或扣次。危机、审核不可用和生成失败先持久化活动终态，再 best-effort 结算额度；终态写入失败必须向客户端返回可重试错误。若服务进程死在上游已应答而检查点 SQL 尚未提交的窗口，租约过期后仍可能重做该次计算；迟到令牌不能再覆盖新 worker 或入账，不承诺远端调用 exactly-once。

**审查修复与边界。** 独立复审的阻断已按以下边界关闭：完整修复话/评分输出在审核前写入短时加密检查点，审核故障重试只重放审核与解析，不再重算已有完整输出；检查点过期后原键返回 `409` 而不是重新生成，只有新请求编号可重新提交；过期键先判永久过期再判派生 `failed` 状态，连续重试不会被误映射为 `500`；检查和终态写入都校验当前工作令牌，旧 worker 不能把新 worker 的 `active` 覆盖成终态，也不能清除过期的检查点栅栏；输入审核 allow 后、生成派发前、备用轮输入审核前以及保存未审核检查点前均重查复盘授权及关联来源，撤权后既不发起下一次审核/评分模型调用，也不保存完整返回。审核不可用的评分调用仍可在最终成功事务中关联唯一评分，且不会因此重复扣次。另保留既有处置：保存前重查原始来源；危机和审核终态先落库、额度收尾失败不反向覆盖终态；删除复盘保留账号内请求键墓碑，原内容与改内容重放均为 `409`；修复话拒绝 ASCII `.` 开启下一句及 `。！？!?．` 仅标点内容，同时保留 `3.5` 这类数字小数。进程在“上游已应答、检查点 SQL 尚未提交”窗口崩溃时仍不承诺远端 exactly-once；`全怪你` 一类语义变体不能由有限词表证明，仍需真实模型和人工话术验收。

**T26 接点。** `Bus.ScoreCompleted.Subscribe` 订阅 T03 `events.Score`（八个整数及 `user_id,activity_id,source_id,kind,occurred_at`）。提交后及分钟维护任务投递；无订阅者保留待发位。T04 锁内从仍有权访问的源解密提取数值，订阅者事务内写投影；所有订阅者成功才确认，失败则投影、确认一同回滚。不重置原始时间，超过 30 天不再交付。T26 需按 `source_id` 去重并实现自身导出。T19 同时接入时按 kind 分派 decoder，不能用一种源的 AAD 解另一种。

**隐私与版本。** `reviews.json` 是 `Data.Export` 的必需分区：每个现存操作一项，完成条目含原提交、修复话及带理由的评分。T06 导出结算，T10 导出关联调用元数据；不导出指纹、工作令牌或密钥。日记、检查点、评分用 T04 AES-GCM，AAD 分别绑定账号、活动或评分源及字段；场景用账号内盲索引筛选。标记/事件删除后外键置空，不再从日记密文恢复旧链接。删除复盘、关系人或注销级联清除源、待发位、成长副本与可关联调用；日累计不因删单条复盘而退款。无通用导出 HTTP 新路由，属 T35。

### 修复话术验收（均为合成示例）

在上述原生 PG17 与受控 TLS 联验中，还同时保持一个评分输出审核请求在途。第二个客户端先读到 `202`，再用原键跨过检查点边界得到非重试 `409`。放行旧审核后，旧 worker 不能把结果改回成功；原键仍是 `409`，两类模型的调用数没有增加、评分和净扣次仍为零。测试仅调整一次性库的 `generated_at` 模拟 15 分钟，不依赖等待真实时间。

# T16 · 手机 App 脚手架

<a id="t16-current-integration"></a>
## 范围和入口

- `app/` 是 Flutter **3.38.10** / Dart **3.10.9** 的 iOS、Android 工程；SwiftPM、iOS 15+，Android minSdk 24。启动见 `app/README.md`。首版无登录/测评/采集业务页，未申请麦克风或健康权限；现行客户端已包含登录与自评入口，见 [app/README](../../app/README.md)。四个根路由 `/practice`、`/live`、`/growth`、`/me` 共用中文导航、系统明暗主题和可滚动布局。
- **加页面**：在 `lib/features/<功能>/` 创建页面及状态，在 `main.dart` 的 `onGenerateRoute` 注册子路由；四个根入口用 `features/home/shell.dart` 的 `Section`。子页 `pushNamed`，同级根入口替换而不堆栈。复用 `core/theme.dart` 的主题与 `StatusPanel`；页面处理加载、错误与重试，不展示异常对象或响应正文。
- **调接口**：在 Consumer 内取 `final api = await ref.read(apiProvider.future)`。`MobileEndpoints(api)`（[`core/endpoints.g.dart`](../../app/lib/core/endpoints.g.dart)）由 [生成器](../../app/tool/generate_api.py) 从当前 [App 契约](../../docs/api/app.yaml) 生成，暴露与契约同名的移动端操作（首版 63 项；静态复核至 `f8b3973` 为 64 项），路径与查询参数有类型，JSON 请求体和响应保留 wire 字段；`/v1/payment-notifications/` 前缀的 3 个渠道入站支付通知由渠道发往服务端，不属于移动端，生成器跳过。举例：`await MobileEndpoints(api).listSessions(scope: scope, limit: 20)`。ZIP 用字节流，不当 JSON，不自动落盘。已登录操作必须显式传入发起时捕获的 `AccountScope`，不从请求体传用户 ID。
- **登录与退出**：校验登录响应后 `final scope = await api.sessions.activate(Tokens.fromJson(result))`；冷启动 `apiProvider` 恢复后才开放页面。令牌过期预刷；401 使用同账号的单飞刷新，原请求最多重发一次；刷新被拒则清本机状态。退出必须调用 **`api.logout(scope)`**（不是仅调用 HTTP 撤销接口）：先使旧句柄失效、销毁密钥并清文件，再尝试远端撤销；离线也不保留活跃数据。切换账号重新 `activate`，不复用旧句柄。业务 provider 按 scope 分组并在退出时丢弃内存展示，不在后台回调里重新取 `sessions.active`。
- **存储**：`Sessions.put/get/remove(scope, CacheKind, id, …)` 管理续答、草稿、录音字节和队列。平台安全存储放令牌与随机会话数据钥；私有 cache 中仅写 AES-GCM 密文，附加认证数据含用户、用途及 ID。模拟/不同服务源互不复用；相同账号重新登录也不会恢复已退出会话。录音读取和冷启动前清 3 天过期件。后续窗口队列按渠道独立建 key，撤回时调用 `remove`；不要存未加密录音路径或另起全局队列。
- **流式回复**：`api.messages(scope, sessionId, clientMessageId, text)` 按 UTF-8 和 SSE 行/空行组帧；`fragment` 只临时显示；`replySaved` 后从历史确认；`safety` 或 `moderationUnavailable` 须分别替换此前片段；`inProgress` 或流中断按会话查历史，不视作主动退出，不发起新扣次。重试沿用原 `clientMessageId`。
- **授权**：每次准备读传感器时取 `final gate = await ref.read(consentProvider.future)`，调用 `gate.readIfAllowed(scope, CollectionPurpose.health, systemGranted: checkOS, beginRead: startOneRead)`。`checkOS` 只检查，不申请；授权按当前账号分页读取，会员须未到期，录音保留另需 `voice` 和 `audio_retention`。无法确认一律不读；不可缓存返回的布尔值或拿一次检查开启永久订阅。手动标记不经过此门。
- **模拟数据**：不传任何配置即读契约 200 示例（非持久化假后端）；设置单一 `--dart-define=APP_ENDPOINT=https://<测试源站>` 并重新运行即改为真实 HTTP。`app/tool/generate_api.py` 从 `docs/api/app.yaml` 生成目录、访问方法、离线 JSON/ZIP/SSE 示例，不手改生成物。契约变更后运行同脚本不加 `--check`。

## 验证命令及实际结果（首版历史回执）

以下是本卡首版及随后 CI 驱动修订的历史回执，不是对当前客户端或现行调用指引的验证；命令、运行编号、失败与通过的时序及未验证条件原样保留。

```sh
# 在仓库根；Python 环境安装 scripts/contract-requirements.txt 或 PyYAML==6.0.3
python3 app/tool/generate_api.py --check
export PATH="$PWD/build/toolchains/flutter/bin:$PATH"
cd app
flutter pub get --enforce-lockfile
dart format --output=none --set-exit-if-changed lib test integration_test
flutter analyze --no-pub
flutter test --no-pub -r expanded
flutter test -d <模拟器ID> integration_test/smoke_test.dart
```

- **本机自动化**：契约产物一致、分析无问题；9 项测试覆盖双账号及迟到的刷新/队列、密文落盘、录音过期、回环 HTTP、并发刷新与 401、5 类 SSE 分帧/断线、采集拒绝、320 宽大字号切页。回环 HTTP 是真实 socket + 测试响应，不是服务端业务联调。
- **本机 iOS**：Xcode 27.2，iPhone 17 Pro / iOS 26.5 Simulator，安装并运行 `smoke_test.dart`，`All tests passed`。测试实际使用插件保存/恢复令牌及加密数据、四页导航、A 登出后 B 读不到四类缓存且 A 不能发请求。选择 iOS 15+ 是因本机 Xcode 不支持模板默认的 13.0 部署目标。
- **CI 驱动**：首次线上运行 `44897791536` 的 Android 通过；iOS 两次均构建成功但在测试驱动发现调试端口时超时（零测试），不是通过。iOS 作业改用 `tool/ios_smoke.sh <已启动的模拟器ID>`：直接安装并启动测试入口，在本次启动的应用容器中读取 Flutter 测试绑定完成后的非空结果；失败、缺失或超时均失败。不会因进程成功启动而报通过。线上运行 `44901911150` 的 iOS 作业 `136839387564` 已通过；其安卓前置静态检查发现测试回执入口当时在 `tool/` 引用了仅供测试的 API，已将 Dart 入口移至 `test/support/`，未忽略检查。本机 iPhone 17 / iOS 26.5 实跑该驱动返回 `PASS 1`；检验过程中也确认失败的测试会生成 FAIL 并令脚本非零退出。
- **线上双端**：独立工作流 `.github/workflows/mobile-t16.yml`，`ios` 启动 iPhone Simulator；`android` 启动 API 35 x86_64 Pixel 模拟器，两者运行相同集成测试。用 `gh run list -w mobile-t16.yml --commit <本卡SHA>` 及 `gh run view <run-id>` 查该提交实际结论；本机无 Android SDK/AVD，不将本机 widget 测试计为 Android 通过。

## 未验证条件

未测试真机硬件密钥强度、卸载恢复/厂商备份、生产签名或商店审核。系统授权、会员与撤回组合使用可控输入验证，没有真实传感器采集；真实登录/令牌轮换/撤销和真实对练 SSE 仍需后端联调。示例不会执行服务端审核、结算、支付或模拟所有业务状态。

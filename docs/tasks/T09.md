# T09 · 模型网关核心

## 范围和入口

`server/internal/gateway` 是内部模块，没有新增 HTTP 接口。T10 组合层在启动时调用 `runtime.StartGateway(startupCtx)`，在关闭 `runtime` 前 `defer catalog.Close()`，再以 `catalog.ForTasks(gateway.Model, resolveTask)` 构造业务依赖。`resolveTask(context.Context, string) (uuid.UUID, error)` 由路由层注入；网关每次分发都校验返回的配置，不信任选中的 UUID 自带授权。审核可用 `gateway.Moderation` 创建同样受限的入口；模型准入不能跨作审核准入。

业务侧示例（`chat` 是注入的 `*gateway.Chat`，`messages` 为 `[]gateway.Message`）：

```go
out, err := chat.Chat(ctx, "scoring", gateway.Request{
    Mode: gateway.JSONObject, Messages: messages,
})
if err != nil { return err }
return json.Unmarshal(out.Object, &score) // 业务仍须校验字段、类型和范围
```

- 普通调用用 `gateway.Text`，消费 `out.Text`；JSON 模式要求上游返回一个完整 JSON 对象，非模式验证。流式用 `gateway.Stream` 和同步的 `OnDelta func(string) error`：回调接的是**未经审核的内部片段**，不能直通客户端。回调错误立即断流；不累积整段回复；只有正常停止和 `[DONE]` 才算完整。
- 迁移 `20261121000600_gateway_admission` 不预置任何供应商，旧启用配置先停用。受信运营人员先独立核对并录入 `provider_admissions`：精确服务商、HTTPS API 基址（不含 `/chat/completions`）、合同覆盖的模型（具体模型名，或有全端点条款时显式填 `*`）、用途类型和说明、实际发送字段、境内处理和存储、不出境、最长留存天数（0 表示不留存）、删除途径和条款凭据。优先选择不留存或短留存。更换去向必须重新核准；主备无豁免。撤销时在一个 PG 事务中先停用受影响配置，再撤材料，提交后 `Notify`。无证明不能测试连通性。
- **接兼容模型**：在已审端点下用 `catalog.Save(ctx, cfg, key)` 写一条 `Config`（稳定 UUID、显示名、服务商、基址、实际模型名、准入引用、`Kind: gateway.Model`、`Protocol: "openai_compatible"`、启停状态）。这是特权管理层的完整写入原语，不是面向业务或 HTTP 暴露的改模能力。密钥单独传入，复用 T04 的 AES-GCM 信封，AAD 绑定表、字段与配置 UUID。热缓存只存密文，按调用解密。不写调用日志或持久化正文。
- **接不兼容服务商**：在本包新增实现 `adapter.chat` 的协议适配器，在 `builtinAdapters` 注册新协议名。核对其实际发送字段、目的、派生路径与准入契约，若不同须先扩展迁移和验证；不可接受业务传入端点/模型/认证头。保持 HTTPS、不可重定向、不走环境代理、有限读取、可取消、错误不回显上游正文；为三种模式和异常结束添加本地假服务测试。只要协议相同（包括兼容部署的 vLLM），无需为每个品牌复制适配器。
- `Save` 提交 PG 后向普通 Redis 的 `gateway:config:changed` 发布固定消息。订阅方在一致性事务内重读配置，原子替换快照；分发前另查 PG 随机版本标记，丢通知也不能继续使用已撤配置，PG 不可用则不分发。变更对下一次调用生效，不撤回已经发出的请求。`ErrNotification` 表示已提交、广播失败，重试 `Notify` 而不是假定写入已回滚。

## 验证命令及实际结果

- `cd server && go test ./internal/gateway`：本地 TLS 假服务核对请求路径、Bearer、发送字段、普通回复、真实 SSE 分段 / 消费方中止、JSON 对象及 vLLM 兼容的流式用量尾帧；覆盖上游错误、非法 JSON 结果、流截断、拒绝重定向及非法入参不选路。
- `./server/tests/migrations.sh`：临时 PG17 全部迁移 up → invariants → down 至空 → 再次 up。
- `./server/tests/gateway.sh`：临时 PG17 / Redis 8.2 / TLS 假上游，执行 `go test -race -tags integration -count=1 ./internal/gateway`；`TestGatewayHotUpdate` 检查空白条款与未知留存被拒绝、端点/模型/用途错配、字段密文与跨行解密拒绝、同进程收到 Redis 通知并使用新模型名/密钥，以及无通知撤销后不再触达假服务。

现有 `T04 server` CI 通过 `./server/tests/runtime.sh` 自动执行同一组集成测试；`Verify` 负责迁移上下行，`Migration history` 检查相对已发布迁移的增序与不可变性。

## 未验证条件

仅验证虚构数据、临时密钥、回环 TLS 假上游。未触达真实厂商；数据库约束不是对合同真伪、实际地理位置、留存或删除履约的证明。未验生产 KMS、生产网络策略、真实模型输出质量或厂商协议变体。

# T19 · 情景对练服务

**交付边界**：服务端，不改 Flutter、不配置生产供应商。入口为 `server/internal/training`、`server/internal/service/training_{http,runtime}.go`；合成联调入口 `./server/tests/t19-wire.sh`。真实服务链路与真人评测的证据分列如下。

## 范围和入口：T20 / T26 接入

| 操作 | 服务端契约 |
|---|---|
| `GET /v1/levels` | 10 个固定 ID，支持 `scene`、`difficulty=1…3`、`limit/cursor`；五类场景、四种单项目标。`catalog.go` 同时定义对手身份、动机和冲突。|
| `POST /v1/sessions` | 客户端 `request_id` 即会话 ID；选 `level_id` **或** `scene+scenario`，可选 `contact_id`。首次先告知保留期并明确授权。重复相同输入取回原场，不同合法输入 409。保存当时的关卡配置，不因后来修订而改变历史评分分支。创建不生成、不扣次。|
| `POST /v1/sessions/:id/messages` | `{client_message_id,text}`。原 ID、原文重发；`in_progress` 读历史，`reply_saved` 携真实消息 ID 和提交后的账本。另一个操作在当前生成/评分期间返回 409。只有 T10 审过的句子成为 `fragment`；`safety` 和 `moderation_unavailable` 都替换片段，不得渲染成普通回复。普通上游断流在已开启 SSE 后以 EOF 结束，不伪造 `reply_saved`，再 GET 确认状态。|
| `GET /v1/sessions[/:id]` | 仅本人，可取 `messages`（双方按 `seq`）、`settlement`、完成场的 `result`。列表按创建时间降序、ID 破同值；分页游标为本账号上一页最后一个会话 ID。断网、杀客户端或退回列表不调用 exit；重开先 GET，必要时才用原消息 ID 显式重试。|
| `POST …/exit`、`POST …/finish` | 退出与迟到工作者在账号锁内互斥。结束必须至少有一对完整发言。已完成重复 finish 只取原结果，并发未结束返回 409。整场返回 T12 四项、三维、主导 mode、改写和用户轮次；单项只返回 `progress`。评分时危机返回固定安全对象；审核故障返回 503；最终评分失败返回 500，再 GET 核对退款。重练须新 ID；按同关、同模式的上一条完成记录对比，不用另建成绩副本。|

**授权联调前置**：测试账号真实登录、确认告知后 `PUT /v1/me/consents/practice {"version":"v1","granted":true}`。T20 的本地 `notice.v1` 不等于服务端授权记录；没有该记录返回 403，不能静默代签。关系列表展示权限不等于实际使用权；创建和生成复核 T06 `RequireContact`，`Summary` 是事务内 T03 `app.Profile` 适配口，只取 `summary`，不把画像当作系统指令。独立基线使用不推断性格的桩；当前含 T25 的共享注册接 `Profiles.ForModel`（还需关系人用途授权）。不要从历史读取更新关系人的选用顺序。

**部署种子**：迁移 `20261122003019_practice_work` 新增随源级联的工作状态表，并向 T11 `prompt_versions` 幂等插入 `role_play` 不可变草稿 `19000000-1000-4000-8000-000000000001`；down 不破坏历史引用。`cd server && go run ./cmd/practice-seed` 输出同一草稿，核对用，不要重复创建。评分用 `go run ./eval/scoring seed`（T12）。按 T11 为实际准入的主、备用、灰度模型分别发布对应版本，配置两种任务的审核及价格；没有发布不以本地提示词替代。不要用验收夹具配置生产路由。

## 事务、不变量与隐私

- T04 账号锁内认领、写用户轮次并提交，再在事务外调用 T10。T06 的场次 token 与短期 worker UUID 分开；消息 ID 唯一约束是 `(activity_id,client_message_id,role)`。生成不依赖手机连接，受网关 60 秒及业务 80 秒预算限制；迟到工作者保存前必须重新通过账户、授权和 worker 检查。`gateway.Call.Guard` 在每次模型尝试的外部输入审核前、审核后模型调用前、每次输出审核供应商调用前复核登录会话、worker、practice consent 和关系人使用权；流式路径在每次片段发送前再次复核，非流式在完整输出返回前复核。因此撤权后既不会调用备用模型，也不会再向审核供应商发送新一轮正文。进程死亡后工作锁 95 秒失效；首次保存还受 T06 预占租期约束，只有同一操作可以接替，未过期返回进行中。断线不是主动退出。
- 最多 30 个用户轮次、3 万会话 token。入场检查新增文本，发送片段前检查剩余长度，提交前检查整轮与供应商报告用量。未知用量按新增双方正文 UTF-8 字节作保守预算；有用量取该预算与本次输入+输出 token 的较大值。可能提前结束；这是服务端可发送/保存的历史上限，**不是供应商账单上限**。到上限不能再开一轮；若已有完整 AI 轮次，则删除未完成尾部并置 `capped`，仍可 finish 评分；没有完整历史则退款并置 `capped`，finish 返回 409。
- `drill` 为独立源类型，在 T06 **归入 practice 的同一额度池**（包括进行中的预占）；只有全文通过后，首个可取回的 AI 消息和扣次一起提交。会员无账本则 `uncharged`，不冒充免费用户已扣次。以后每条消息不重复扣。已保存后退出保留原扣；首条前退出/生成失败不扣。正常路径下，危机、审核无结论、最终评分失败的终态和 T06 释放或退回**原扣次日**在同一事务提交；若意图或退款事务失败，则先持久终态、保留原 worker 作为补偿标记，由维护循环按同一 token 幂等补退。故障窗口内 GET 可先看到安全终态，但账本可能仍为 `charged`，直到补偿成功才变为 `refunded`。仅审核故障允许重试原操作；`claim` 必须先以原 worker 令牌完成补偿，不能通过同键重试覆盖标记或重新认领，已退的场只有补偿后重试成功才重新结算。
- 会话建立即由数据库分配不可复用评分源 ID。T12 只收到按真实 `role/seq` 还原的对话。完整分的加密 `scores.detail_enc`、成功 `ai_calls.score_id`、终态及待投标记一起提交；单项仅存加密 `drill_progress` 及调度时间，不建 `scores`。提交后投递 `score.completed` 或 `drill.progressed`。无订阅者保留待投；维护循环重投不刷新发生时间，最多 720 小时。订阅者写入和待投标记确认同事务，账号/源/时间不符不消费。当前共享解码按 `practice/review` 分派，不覆盖 T23。
- 场景、双方消息、评分理由/改写均为字段加密信封，AAD 绑定用户、记录 ID 和用途。调用审计与事件不带文本。T04 `training.json` 导出本人创建输入、双方发言、分项、结算和删除源键；会话、关系人、账号清理均随源级联。只删除内容不会退次数；账号删除清理日汇总由 T06 负责。

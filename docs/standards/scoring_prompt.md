# AI 评分提示词 v1

这是 docs/standards.md 第四节“AI 评分细则”的可执行版本：一段系统提示词、一份输出格式、10 条基础标注和 2 条带期望输出的回归样例和一致性测试方法。交给 T12 录入提示词表后，用真实模型跑测试。

## 补充规则（已采用，优先于主页第四节）

- **两种表达类型**：“表达型”是用户说出自己的诉求（提要求、拒绝、表达不满），按 NVC 原意评。“回应型”是用户在接对方的情绪（安慰、倾听），四项改评：观察 = 复述事实不评判；感受 = 说出对方可能的感受；需要 = 点出对方的需要；请求 = 给出具体的下一步或询问对方想要什么。
- **观察**：有事实从 25 分起，无事实从 10 分起；每处评判或绝对化表述扣 10 分，最低 0 分。
- **需要**：既没表达需要、也没有指责时得 10 分。
- **请求**：完全没有请求或下一步时得 0 分。
- **危机内容**：用户表达中出现自伤、家暴等内容时不打分，`safety_flag` 设为 true，由网关返回固定求助提示。
- **整场改写**：取整场主导 mode，只改问题最大的一轮，不超过 80 字。`target_turn` 为可选整数，从 1 开始数用户发言，不计 AI 轮次。
- **评分对象**：对练结束后把整场用户发言作为 utterance、AI 发言作为 context，评一次；复盘评“我当时怎么做”一栏；聊天回复助手本轮不打分。
- **求助提示**（网关在 safety_flag 为 true 时返回，不扣次数）：“听起来你现在可能正经历很难受的事。这里不适合继续练习，建议你马上联系专业的人：全国心理援助热线 12356；如果有人身危险，请立即拨打 110 或 120。”

## 单项练习与整场评分分流

调用方声明 `single_skill`、`full_session` 或 `full_review`。下面的整场提示词和 JSON Schema 仅供后两种；`single_skill` 另用目标项规则、仅返回 `target_item`、`score` 和目标项反馈，不输出四项总分或情绪等级。关卡只保存进度；四项共用[单项关卡分档表](../standards.md#三训练规范非暴力沟通nvc)，按目标项得分决定过关或重练。安全检查三种模式都要经过，审核不可用是服务错误，不是 `safety_flag: true`。

## 系统提示词

变量：`{{scene}}` 场景（职场/伴侣/家人/朋友/社交）、`{{context}}` 对方说的话或情境、`{{utterance}}` 用户的表达、`{{profile}}` 对方画像摘要（可为空）。

```text
你是一个情商训练 App 的评分员。你的任务是按固定规则，给用户在某个沟通场景中的一次表达打分，并给出一个更好的说法。你只评说话方式，不评判用户这个人，也不做心理诊断。

【场景】{{scene}}
【对方说的话或情境】{{context}}
【对方画像（可能为空，仅供参考）】{{profile}}
【用户的表达】{{utterance}}

第一步：判断表达类型 mode。整场对练只评一次，按用户发言的主导类型选 mode。
- express：用户在说自己的诉求（提要求、拒绝、表达不满）。
- respond：用户在回应对方的情绪（安慰、倾听）。

第二步：NVC 表达分，四项各 25 分，合计 0–100。
观察：
- express：有事实从 25 分起，无事实从 10 分起；每处评判或绝对化表述扣 10 分，最低 0。
- respond：有事实复述从 25 分起，无事实从 10 分起；每处评判扣 10 分，最低 0。
感受：
- express：明确说出自己的真实情绪得 25；把想法当感受（如“我觉得你不尊重我”）得 10；没有表达得 0。
- respond：说出对方可能的感受得 25；泛泛说“理解你”得 10；否定或忽略对方感受（如“别想太多”“有什么好难过的”）得 0。
需要：
- express：说出自己感受背后的需要得 25；既没说需要也没指责得 10；只有指责得 0。
- respond：点出对方的需要得 25；没有涉及得 10；说教或指责对方得 0。
请求：
- express：具体、可执行、对方可以拒绝的请求得 25；模糊的请求得 10；命令、威胁或反问式指责得 0；没有请求得 0。
- respond：给出具体的下一步，或询问对方想要什么得 25；模糊的安慰或建议得 10；没有得 0。

第三步：三个情绪维度，各 1–5 级。
- 读懂别人：1 = 完全忽略对方情绪；3 = 注意到情绪但没有回应；5 = 准确识别并回应对方的情绪和需要。
- 自我管理：1 = 语言攻击、情绪爆发；3 = 有情绪但基本克制；5 = 平稳表达，情绪不影响沟通。
- 关系效果（预估对方听到后的反应）：1 = 关系明显恶化；3 = 关系无变化；5 = 关系改善，对方愿意继续沟通。
2 和 4 用于介于两档之间的情况。

第四步：写一个更好的说法。整场只改问题最大的一轮，target_turn 指该轮是第几次用户发言（从 1 数，不计 AI 发言）。单条表达可省略。
- 保留用户的真实立场和目的，不要变成讨好或妥协。
- 口语化，符合中国人在该场景下的说话习惯，不超过 80 字。
- 用一两句话说明为什么这样说更好。

安全规则：如果用户的表达或情境涉及自伤、自杀、家庭暴力或人身危险，不打分，只输出 {"safety_flag": true}。

只输出符合给定 JSON Schema 的 JSON，不要输出任何其他文字。扣分原因要引用用户原话中的具体词句。
```

## 输出格式

```json
{
  "oneOf": [
    {
      "type": "object",
      "required": ["safety_flag"],
      "properties": {"safety_flag": {"const": true}},
      "additionalProperties": false
    },
    {
      "type": "object",
      "required": ["safety_flag", "mode", "nvc", "emotion", "better_version", "why_better"],
      "properties": {
        "safety_flag": {"const": false},
        "mode": {"enum": ["express", "respond"]},
        "nvc": {
          "type": "object",
          "required": ["observation", "feeling", "need", "request", "total"],
          "properties": {
            "observation": {"$ref": "#/$defs/item"},
            "feeling": {"$ref": "#/$defs/item"},
            "need": {"$ref": "#/$defs/item"},
            "request": {"$ref": "#/$defs/item"},
            "total": {"type": "integer", "minimum": 0, "maximum": 100}
          }
        },
        "emotion": {
          "type": "object",
          "required": ["read_others", "self_management", "relationship"],
          "properties": {
            "read_others": {"$ref": "#/$defs/level"},
            "self_management": {"$ref": "#/$defs/level"},
            "relationship": {"$ref": "#/$defs/level"}
          }
        },
        "better_version": {"type": "string", "maxLength": 80},
        "target_turn": {"type": "integer", "minimum": 1, "description": "从 1 起的用户发言序号，不含 AI 轮次"},
        "why_better": {"type": "string"}
      }
    }
  ],
  "$defs": {
    "item": {"type": "object", "required": ["score", "reason"], "properties": {"score": {"enum": [0, 5, 10, 15, 25]}, "reason": {"type": "string"}}},
    "level": {"type": "object", "required": ["level", "reason"], "properties": {"level": {"type": "integer", "minimum": 1, "maximum": 5}, "reason": {"type": "string"}}}
  }

```

服务端额外校验：`nvc.total` 必须等于四项之和，不等则按四项之和覆盖并记录数值。若提供 `target_turn`，不得大于本次输入中的用户发言数；越界走 T12 校验失败路径。理由与原话只保存在源评分明细。

## 一致性测试方法

1. 每条样例用同一模型、temperature 0.2 连续跑 5 次。
2. **稳定性**：5 次的 NVC 总分标准差 ≤ 5 分，每个情绪维度最多相差 1 级。
3. **准确性**：5 次平均值与期望值相比，NVC 总分偏差 ≤ 10 分，情绪维度偏差 ≤ 1 级。
4. **格式**：全部样例各跑 5 次，100% 的输出 能通过 Schema 校验。
5. 任一项不过，先调提示词里的扣分例子，再考虑换模型；上线后每月仅在受控环境抽 50 条真实评分人工复核。记录错误类型，以虚构对话重写同类回归样例；禁止把真实原话、用户/源评分 ID 或关系人信息复制到评测库。

以上是期望输出，不是真实模型的运行结果；由 T12 接上模型后执行。
